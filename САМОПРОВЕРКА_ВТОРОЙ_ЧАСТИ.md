# Самопроверка второй части и перевод во вторичные баллы — вводная

Чату тестов, от владельца через оркестратора, 2026-08-12.
Читать после `CLAUDE.md`, `ОРКЕСТРАЦИЯ.md`, `ТЕСТЫ.md`.

## Что просит владелец

Ученик проходит вариант, где часть задач автопроверке не поддаётся.
Порядок такой:

1. проходит тест;
2. после сдачи видит **решение и критерии** по задачам второй части;
3. **сам ставит себе баллы** по этим критериям;
4. первая часть проверена автоматически, баллы сведены — показаны
   первичные, а для полного варианта ещё и вторичные (тестовые).

## Что уже есть (сверено оркестратором по проду и по твоему отчёту §124)

- Шаг «Самопроверка второй части» после сдачи **существует**: задачи
  части 2 кладутся с `points = 0`, ученик проставляет баллы сам.
- В каталоге есть всё нужное: `grade_criteria_html`, `solution_html`,
  `max_points`. Заполненность высокая — физика ЕГЭ: 611 задач части 2,
  решение у **611**, критерии у **598**, `max_points` у **598**;
  математика ЕГЭ: 3782 / решение 3781 / критерии 3755.
- Показ решения и эталона открывается только после сдачи (§52, §60).

**Чего нет вовсе:** таблицы перевода первичных баллов во вторичные —
в схеме нет ни одной подходящей таблицы или колонки.

## Задача

### 1. Проверить и достроить шаг самопроверки

Разведай сначала, что шаг реально показывает сегодня, и скажи в
отчёте. Должно быть: условие задачи, ответ ученика, **решение**,
**критерии**, поле для своего балла с потолком `max_points`.

Обязательные требования:

- **Критериев может не быть** (13 задач физики, 27 математики). Тогда
  так и написать — «критериев к задаче нет», а поле балла оставить с
  потолком из `max_points`; если и его нет — задача в подсчёт не идёт,
  и это видно словами, а не молчаливым нулём.
- Поставленный балл — **не факт, а самооценка**. Хранить отдельно от
  автопроверенных, подписывать соответственно; преподаватель, глядя в
  результат, обязан видеть, что часть баллов ученик поставил себе сам.
- Пересмотреть свою оценку можно, пока вариант не закрыт; каждое
  изменение перезаписывает балл, история не нужна.

### 2. Первичные и вторичные баллы

- **Первичные** — сумма автопроверенных и самооценённых, показывать
  всегда, с разбивкой «часть 1 / часть 2».
- **Вторичные (тестовые) — только для полного варианта** (решение
  владельца 12.08). Полный = собран по одному заданию на каждый номер
  экзамена. Если вариант неполный, тестовый балл **не показывать
  вовсе** и сказать почему: «тестовый балл считается только для полного
  варианта». Пропорция от максимума варианта — ложь: шкала ФИПИ
  нелинейная, и 5 из 7 по одному номеру не превращаются в проценты
  экзамена.
- **Шкала живёт в базе** (решение владельца): таблица вида
  `exam_score_scales(subject, exam_type, year, primary_score,
  secondary_score)`, заполняется миграцией. Ищи официальную шкалу ФИПИ
  на 2026 год; **если не уверен в цифрах — не выдумывай**, покажи
  оркестратору то, что нашёл, и жди подтверждения. Неверная шкала хуже
  отсутствующей: ученик поверит числу.
- Шкала меняется раз в год — предусмотри `year` и выбор действующей,
  чтобы обновление было строкой в таблице, а не правкой кода.

### 3. Чего не делать

- Не трогать автопроверку первой части и правило
  `variant_answer_verdict` — оно одно на всех.
- Не заводить второй механизм выдачи (§58) и второй копии правила
  автопроверяемости (§124).
- Не показывать решения до сдачи — гейт §52/§60 остаётся.

## Порядок

Короткий план оркестратору ДО кода: что шаг показывает сейчас, где
хранится самооценка, как устроена таблица шкалы и откуда взяты цифры.
Миграции — MCP `apply_migration` + файл с именем, точно равным версии в
`schema_migrations`; типы дописывать руками с пометкой (генерация не
переживается контекстом). Номер раздела — хвост+1 в момент записи.
Проверка типов — **`npx tsc -b > log 2>&1; echo $?`** буквально
последним действием (`--noEmit` не проверяет ничего, §117.1). Тест
каждого меняемого файла. Отчёт оркестратору.
