# Шаблоны и групповые курсы: признак в базе и группировка списка — вводная

Чату контура курса, от владельца через оркестратора, 2026-08-09.
Читать после `CLAUDE.md` и `ОРКЕСТРАЦИЯ.md`.

## Что просит владелец

На странице «Курсы» не видно, что курс курсу рознь: «Физика ЕГЭ Шаблон» —
это каркас, из которого копируются курсы групп («Физика ЕГЭ 11А класс»),
но в списке они выглядят одинаково. Владелец выбрал (09.08, из трёх
вариантов): **группировка под шаблоном** — шаблон рисуется главной
карточкой с бейджем, его копии вложенным рядом под ним.

## Факт, сверенный оркестратором по проду 09.08

В `courses` НЕТ ни признака шаблона, ни ссылки «скопирован из»:
шаблонность сейчас живёт только в слове «Шаблон» в названии. Значит
сначала схема, потом интерфейс — группировать по подстроке названия
нельзя, названия владелец меняет.

## Рамка

### 1. Схема

Два поля в `courses`:

- `is_template boolean not null default false`;
- `copied_from_course_id uuid references courses(id) on delete set null`
  — при удалении шаблона копии живут дальше, просто теряют ссылку.

Разметка существующих — в той же миграции, по id (не по названию):
три курса «… Шаблон» → `is_template = true`; «Физика ЕГЭ 11А класс»
(`2e40ec74-4b69-49d4-b7e0-37e388435a20`) → `copied_from_course_id` =
«Физика ЕГЭ Шаблон» (`daf8c6a3-e37f-465d-ac3e-fcadb055342a`);
математику-11А привяжи к её шаблону — id возьми запросом, в отчёте
покажи какой. Сверь итог: шаблонов 3, копий с ссылкой 2 (на сегодня;
перед миграцией пересчитай — владелец создаёт курсы).

### 2. Копирование

Твой же механизм копии (§102): копия ШАБЛОНА получает
`copied_from_course_id` = исходник и `is_template = false` — всегда,
без вопросов пользователю. Копия обычного курса — тоже со ссылкой на
исходник: вреда нет, а картина полнее.

### 3. Настройки курса

Галочка «Это шаблон (каркас курса)» в редактировании курса — для
персонала курса и админа, чтобы будущие курсы размечались без миграций.
Подпись-пояснение обязательна: «Шаблон — каркас. Учеников зачисляют в
копии, не в шаблон».

### 4. Список «Курсы»

- Шаблон — главная карточка: бейдж «Шаблон», лёгкое визуальное отличие
  (приглушённый фон или рамка — реши по месту, у проекта уже есть язык
  бейджей: «черновик» жёлтый).
- Его копии — вложенным рядом под шаблоном, карточки обычные, с
  отступом или соединительной линией, чтобы читалось «это дети каркаса».
- Курсы без ссылки и без признака — отдельным рядом ниже, как сейчас.
- Бейдж «черновик» остаётся на карточке где был; отдельная секция
  «Черновики» при группировке теряет смысл — убери, черновиковость
  видна бейджем. Если сочтёшь иначе — скажи в отчёте почему.
- Пустой шаблон без копий — просто карточка с бейджем, без пустой
  «полки детей».

### 5. Чего не делать

- Ученику шаблоны и так не видны (он видит курсы своих групп) — гейтов
  не добавлять, RLS не трогать.
- Никакой логики «синхронизации копии с шаблоном» — это отдельная
  большая тема, владелец её не просил.
- Каталог, покупка, витрина — не трогать.

## Порядок

Миграция — MCP `apply_migration` + файл в `supabase/migrations/` с
именем, точно равным версии в `schema_migrations`; типы перегенерировать
MCP, руками не дописывать (§75). Номер раздела — хвост+1 в момент записи
(сейчас хвост §112). Полный `npx tsc --noEmit > log 2>&1; echo $?`
**буквально последним действием**, тест каждого меняемого файла
(включая тест самой страницы «Курсы»). Отчёт оркестратору.
