# Харнесс для скриншотов

Мобильные скриншоты (390×844) снимаются на живом Vite-деве с ПОДМЕНЁННЫМ
Supabase, а не на проде и не на демо-учётках (`board/014`). Никаких настоящих
людей и данных здесь нет — весь `fixtures.mjs` выдуман.

Playwright перехватывает каждый запрос к Supabase (`context.route`) и отвечает
сам, эмулируя PostgREST/Storage/Auth поверх фиктивного адреса
`https://harness.invalid`. Всё, что летит на любой другой адрес (реальный
Supabase, Vercel Analytics, шрифты, видео-плеер), молча обрывается
(`route.abort()`) — прод тронуть невозможно даже случайно.

## Файлы

| Файл | Что делает |
|---|---|
| `lib.mjs` | Мини-PostgREST: фильтры (`eq`/`in`/`like`/…), `select` с embed-таблицами, RPC, Storage (signed URL → локальный файл-заглушка, `list`/`upload` поверх `fixtures.storage`), сессия/`localStorage`. |
| `fixtures.mjs` | Все выдуманные данные: профили, курсы, темы, задачи, ДЗ, варианты, уведомления. `baseFixtures(persona)` собирает набор таблиц + RPC под роль. |
| `scenes.mjs` | Список сцен: кто (`persona`), какой URL, какие действия (клик/фокус/скролл/файлы) до снимка, чем показывать (`media`). |
| `assets.mjs` | Рисует заглушки: фото решения от руки, таблицу, формулу, график, PDF. Разовый скрипт — держите результат, не гоняйте на каждый прогон. |
| `tour.mjs` | Обходит `scenes.mjs`, для каждой сцены сохраняет `<имя>.png` (viewport) и `<имя>-full.png` (вся страница, если `full !== false`), плюс лог запросов и предупреждение о горизонтальном переполнении. |
| `discover.mjs` | Грубый обход списка маршрутов с ПОЧТИ пустыми фикстурами — что запрашивает экран, если у него нет данных. Полезен, когда снимаете совсем новый экран и не знаете, какие таблицы/RPC он трогает. |
| `probe.mjs` | Для готовых сцен из `scenes.mjs` печатает, какие элементы вылезают за 390px. Быстрее, чем разглядывать скриншот пиксель в пиксель. |

## Как поставить и запустить

1. Установить зависимости репозитория как обычно (`npm ci`/`npm install`) —
   отдельного `package.json` у харнесса нет, он использует
   `@playwright/test` из корня.
2. Поднять dev-сервер **с адресом Supabase, указывающим на харнесс**:
   ```bash
   VITE_SUPABASE_URL=https://harness.invalid VITE_SUPABASE_ANON_KEY=harness-anon-key npm run dev -- --port 5199 --strictPort
   ```
   `.env`/`.env.local` трогать не надо — переменные окружения шелла
   перекрывают файл `.env` для тех же ключей. Порт `5199` жёстко зашит в
   `lib.mjs` (`BASE`); если сервер поднят на другом порту, снимки уйдут не
   туда.
3. Один раз сгенерировать заглушки картинок (перегенерировать нужно, только
   если поменяли `assets.mjs`):
   ```bash
   node e2e/harness/assets.mjs
   ```
4. Прогнать все сцены или отфильтровать по подстроке имени:
   ```bash
   node e2e/harness/tour.mjs
   node e2e/harness/tour.mjs topic-tasks
   ```
   **Печатный вид — `media: 'print'` у сцены (§217).** Печатный лист отчёта
   живёт в портале `document.body` и показывается ТОЛЬКО правилами
   `@media print` (`#root` на печати выключен целиком). Без переключения
   носителя снимок «печати» неотличим от снимка экрана — на нём просто тот же
   кабинет. `tour.mjs` ставит носитель каждой сцене (`s.media ?? 'screen'`),
   поэтому печатная сцена не «заражает» следующую за ней: контексты общие на
   персону и ширину.

   Пара сцен `o07-student-report` / `o07-student-report-print` существует
   ровно затем, чтобы проверить одно: внутренняя заметка преподавателя есть
   на экране и её НЕТ на листе. На печатном снимке жёлтого блока с заметкой
   быть не должно вовсе.

   Второй аргумент — ширина, и он не для удобства (§211). Фикстуры — обычные
   экспортируемые массивы, один набор на ПРОЦЕСС: сцена, которая пишет в базу
   (поворот страницы, «В архив», загрузка файла), оставляет след, и сцена с
   тем же именем на другой ширине стартует уже не с чистого места. Пары
   «до/после» из-за этого ломаются молча. Прогоняйте такие сцены по ширине,
   каждую своим процессом:
   ```bash
   node e2e/harness/tour.mjs o06-rotate 1280
   node e2e/harness/tour.mjs o06-rotate 390
   ```
   Скрипты читают и пишут пути вида `screenshots/harness/...` **относительно
   текущей директории запуска** — запускайте из корня репозитория (там же,
   где `npm run dev`), а не из `e2e/harness`. Сами скриншоты и лог — в
   `screenshots/harness/tour/`; всё дерево `screenshots/` в `.gitignore`,
   в коммит они не попадут, даже если запустить харнесс из `e2e/harness`.
5. Смотреть `screenshots/harness/tour.log` — там для каждой сцены список
   запросов и строка `OVERFLOW …`, если `scrollWidth` страницы больше 390.
   Смотреть `ACTION-FAIL` в том же логе — значит, селектор действия не нашёл
   элемент (обычно: элемент ещё не отрисовался, добавьте `wait` перед
   действием, или на элементе нет узнаваемого текста — ищите
   `data-testid`, они уже расставлены в модалках).

## Как добавить сцену

Дописать объект в массив `scenes` (`scenes.mjs`):

```js
{ persona: 'student', name: 's-имя-сцены', url: '/путь', actions: [
  { clickSel: '[data-testid="что-то"]' },
  { wait: 800 },
] },
```

- `persona`: `student` | `owner` | `guest` — набор фикстур и сессия берутся
  из `personas` в `fixtures.mjs`. `owner` — это одновременно преподаватель и
  админ школы (`staffProfileId`), как на проде у владельца.
- `actions` выполняются по порядку: `click` (текст, `getByText`), `clickSel`
  (CSS/Playwright-селектор, включая `:has-text()`), `clickRole` (роль +
  имя), `fill`, `focus`, `wait` (мс), `scroll` (`window.scrollTo(0, y)`),
  `eval` (произвольный `page.evaluate`), `files`/`chooseFiles` (загрузка из
  `assets/`), `goto` (переход без пересоздания контекста).
- Провалившееся действие не роняет прогон — пишется `ACTION-FAIL` в лог, и
  скриншот всё равно снимается в том состоянии, в каком есть. Это специально:
  один сломанный селектор не должен обнулить остальные 80 сцен.
- `width`/`height` — по умолчанию 390×844. Отдельная секция сцен внизу файла
  дублирует самые плотные экраны на 360 — не убирайте её без причины,
  ловит переполнения, которых на 390 не видно.
- `full: false` — не снимать `-full.png` (вся страница). Ставьте на модалках
  и оверлеях с `position: fixed`: `fullPage`-скриншот у Playwright разворачивает
  document по высоте и рисует под модалкой то, что осталось в потоке
  документа под ней, — получается двойная картинка, а не «вся модалка».
  Смотрите не `-full.png`, а обычный снимок; если контента больше 844px,
  доскрольте до него отдельным `eval`, как в `o03-course-program-tasks`.

## Файлы в бакете (§195)

`fixtures.storage` — объект `{ '<бакет>': [{ name, size, updated_at }] }`, где
`name` — ПОЛНЫЙ ключ объекта (`physics-ege/kin/fig-1.png`). Из него `lib.mjs`
отвечает на `storage.list(prefix)`: файлы прямо в папке — строками с
метаданными, вложенные папки — агрегатом без `id` и без `metadata`, как
настоящий Storage.

`storage.upload` тоже живой: он кладёт объект в этот же массив, а повторная
заливка того же ключа без `upsert` отвечает 409 «The resource already exists».
Поэтому сцена «в папке три файла» снимается тем же действием, что делает
человек, а не подложенным списком. Размер залитого файла харнесс проставить не
может (Playwright не отдаёт тело multipart-запроса с файлом из `setInputFiles`)
— он пишет `null`, и экран честно показывает «—».

## Как добавить выдуманную строку

Все данные — в `fixtures.mjs`, обычные экспортируемые массивы/объекты
(`profiles`, `courses`, `topics`, …) плюс `baseFixtures(persona)`, который
собирает из них `{ tables, rpc, functions }` для `lib.mjs`. Три правила:

- **Только выдумка.** Ни один email, имя, номер, adres — не должен совпадать
  с настоящим человеком. Имена берутся из `NAMES`, id — из `IDS` (утильная
  `U(prefix, n)` штампует детерминированные UUID вида
  `a000000-0000-4000-8000-000000000001` — по префиксу видно, какая это
  сущность, не запоминая рандомные UUID).
- **RPC можно объявить функцией**, а не только статичным значением — она
  получает `(body, url)` и решает по `body.p_topic_id`/что угодно. Пример —
  `topic_tasks_for_student` в конце `fixtures.mjs`: одни и те же 7 задач
  возвращаются только для темы 1, для остальных тем — пустой список, как
  ответила бы настоящая RLS-функция без прав.
- **Не разошлась ли новая строка с реальной схемой** — проверяйте
  `discover.mjs` или просто открывайте сцену и смотрите
  `screenshots/harness/tour.log`: если экран ждёт таблицу/RPC, которых нет в
  фикстурах, будет либо пустой список (для таблиц — `fx.tables[table] ??
  []`), либо `null` (для RPC), и лог покажет сам запрос с именем и фильтрами
  — по нему сразу видно, что добавить.

Сцены **`o05-collections`** (390), **`-wide`** (1280) и **`-archived`** (1280)
— §188 (board/041): список «Мои подборки». В `task_collections` фикстур пять
строк: три своих неархивных (их и видно), архивная и чужая — чтобы на снимке
было видно, что фильтры хука работают, а не что строк просто нет. Даты правки
у двух первых считаются от РЕАЛЬНОГО времени прогона, а не от `NOW` фикстур:
формат строки списка («сегодня в 10:16», «вчера в 18:40») иначе на снимке не
появился бы никогда. В логе на этих сценах ровно два запроса подборок —
`task_collections` и один `task_collection_items` с `in.(…)` по всем трём id;
если их станет больше, значит завёлся N+1. `-archived` жмёт «В архив» на
первой строке: строка исчезает, в логе `PATCH task_collections id=eq.…`.

Сцены **`o05-print-formulas`** / **`-2`** (390 и 1280) и
**`o04-catalog-task-formula`** — §205 (board/056): печатный лист подборки, в
которой ВСЁ содержимое задач — формулы картинками SVG (`class="math"` в
строке, `class="math-display"` блоком). Такие подборки печатает владелец по
математике, растровых иллюстраций там нет вовсе. Заглушки формул —
`formula-*.svg` в `assets.mjs`; их натуральные размеры (186×25, 146×49,
120×55, 516×645, 640×1835) сняты с настоящего экспорта владельца и в харнессе
воспроизводят его лист до пункта. Менять эти числа без нового замера нельзя:
в печати размер формулы на бумаге считается именно от натурального размера
файла. `lib.mjs` отдаёт `.svg` по имени файла и с `image/svg+xml` — растр
вместо вектора сломал бы замер. Сцена жмёт «Пояснения»: блочные формулы живут
в разборе.
