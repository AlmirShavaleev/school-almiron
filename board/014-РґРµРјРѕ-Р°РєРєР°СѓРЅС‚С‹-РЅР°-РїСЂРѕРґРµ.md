## Владельцу — руками, до кода, сегодня

В панели Supabase: Authentication → Users → найти каждого из списка →
меню «…» → **Ban user**. Начать с двух админов и преподавателей —
это две минуты. Бан, а не удаление: у `alex@demo.ru` есть зачисление и
связи (владелец тестировал на нём распределение), удаление потянет за
собой строки. Если демо-ученик для проб нужен — оставь **одного**,
поменяй ему пароль на случайный и никому не показывай.

Через оркестратора этого делать нельзя: он не трогает учётные записи и
настройки безопасности — это правило, а не ограничение инструмента.

   блок `DEMO_ACCOUNTS` целиком (кнопки и так скрыты в проде, но

   локально скриптом, пароли не хранятся в репозитории».
2. `scripts/seed-users.mjs` и `e2e/*`: пароль — из переменной
   окружения (`SEED_PASSWORD`), без значения по умолчанию; нет
   переменной — скрипт останавливается с понятным текстом. Сид должен
   отказываться работать против боевого адреса проекта (проверка
   `SUPABASE_URL` на ref `kthfozyfruorwjhvvsbw`).
3. `PROJECT_STATE.md` — исторические упоминания пароля не переписывать
   (журнал), но в §160 сказать, что пароль отозван и учётки закрыты.
4. Grep по всему репозиторию: строки `demo123` после работы остаются
   только в исторических разделах `PROJECT_STATE`.

## Правило с этого дня

Демо-учётка в боевой базе — это боевая учётка. Экраны снимаются на
харнессе с выдуманными данными (`screenshots/mobile-audit/harness/`),
dev-сервер для скриншотов **не смотрит на прод**. Записано в
`РАБОЧИЙ_ПРОЦЕСС.md`.
