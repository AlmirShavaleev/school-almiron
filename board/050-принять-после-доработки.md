# 050 · Принять работу, уже отправленную на доработку

**Статус:** новая
**Кому:** облачный агент оркестратора
**Ветка:** `work/review-after-return`, от `origin/main`
**Раздел PROJECT_STATE:** **§198** — номер выдан оркестратором
**Заведено:** 2026-09-17

## Слова владельца

«Работа на доработке, но я захожу ещё раз и таки принимаю работу».

Сейчас это невозможно, и вот почему буквально. RPC
`topic_homework_review_attempt` в конце делает

```sql
update topic_homework_attempts
   set status = p_decision::text::public.topic_homework_attempt_status
 where id = p_attempt_id
   and status = 'submitted';
if not found then
  raise exception 'Попытка не в статусе «сдано»';
end if;
```

То есть вердикт можно поставить **только** попытке в статусе «сдано».
Как только преподаватель вернул работу (`returned`), путь закрыт: чтобы
принять, ученик обязан сдать заново. А ситуация житейская —
преподаватель вернул, потом разобрался в почерке или ученик объяснил
решение на занятии, и работу надо принять как есть.

## Что сделать

### 1. Миграция: разрешить пересмотр последней попытки

`supabase/migrations/PENDING_198.sql` — новая версия
`topic_homework_review_attempt` (заменяющая, не вторая копия!):

- допустимые исходные статусы: `submitted` (как сейчас) **и**
  `returned`;
- пересматривать можно **только последнюю попытку** ученика по этому
  ДЗ: если у той же пары «ученик + ДЗ» есть попытка с большим
  `attempt_number`, отказ с внятным текстом («ученик уже сдал работу
  заново — открывайте последнюю попытку»). Иначе преподаватель примет
  старую версию работы, а на проверке будет висеть новая;
- при пересмотре в `topic_homework_reviews` добавляется **новая строка**
  (таблица append-only, триггер `topic_homework_reviews_immutable`
  трогать нельзя) — история «вернул, потом принял» сохраняется;
- балл и его проверка по шкале — как сейчас;
- уведомление ученику отправляется той же `topic_homework_enqueue_reviewed`;
- из `accepted` в `returned` **не** переводить (см. вопрос в конце) —
  в этой карточке только доработка → принято.

Права не менять: кто мог проверять, тот и пересматривает
(`topic_homework_attempt_can_review`).

### 2. Экран

Очередь проверки (`HomeworkReviewQueuePage`) сейчас показывает работы,
ждущие проверки. Работа, отправленная на доработку, из очереди уходит —
и добраться до неё, чтобы принять, некуда. Нужно:

- фильтр состояния в очереди пополнить значением «на доработке» (сама
  выборка уже умеет статусы — проверь `useHomeworkReviewQueue` и
  `homeworkQueue.ts`);
- у такой работы в карточке проверки блок вердикта доступен, но с явной
  подписью: «Работа была возвращена на доработку <когда>. Можно принять
  её как есть — ученик получит уведомление»;
- если попытка не последняя — блок вердикта выключен с подсказкой
  «ученик сдал работу заново»; ссылка на последнюю попытку, если её
  дёшево получить.

История вердиктов (было «вернули», стало «принято») должна быть видна
преподавателю в той же карточке — хотя бы строкой «возвращена <дата>,
принята <дата>».

## Границы

- `topic_homework_reviews` остаётся append-only; строки не обновлять и
  не удалять.
- Ученический путь сдачи (`TopicHomeworkStudent`, попытки) не трогать.
- ИИ-проверку, панель, таблицу заданий не трогать — по ним отдельная
  карточка (§199), и файлы у неё те же: **`AiCheckPanel.tsx` не
  открывай вовсе**, а в `HomeworkReviewQueuePage.tsx` меняй только блок
  вердикта и фильтр состояния.

## Приёмка

- SQL-проба в отчёте (под ролями, как в CLAUDE.md): преподаватель
  принимает возвращённую последнюю попытку → успех, в
  `topic_homework_reviews` две строки, статус попытки `accepted`;
  попытка не последняя → отказ с внятным текстом; чужой преподаватель →
  отказ. Пробы **в откатываемом блоке** (`raise exception` в конце
  DO-блока) — прод-данные не менять.
- Тесты: фильтр «на доработке» отдаёт такие работы; блок вердикта
  выключен для не-последней попытки; подпись про возврат видна.
- `npx tsc -b > tsc.log 2>&1; echo $?` последним; патч от `origin/main`
  в `../patches/050-review-after-return.patch`; отчёт.
