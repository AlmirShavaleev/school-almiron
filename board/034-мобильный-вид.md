# 034 · «Мобильный вид»: переключатель для admin/owner, показывающий текущий экран как на телефоне

**Статус:** новая
**Кому:** облачный агент оркестратора
**Ветка:** `work/mobile-preview`, от `origin/main` (`a104348`)
**Раздел PROJECT_STATE:** **§181** — номер выдан оркестратором
**Заведено:** 2026-09-15

## Просьба владельца

«Можно у админа такую же плашечку, только всё преобразующую в мобильный
вид. Типа вид от ученика, учителя, админ — и мобильный вид. Он поверх
всех функций.»

То есть рядом с переключателем «Администратор | Учитель | Ученик»
(`StaffModeSwitch`, §178) нужна **ещё одна кнопка — «Телефон»**, которая не
меняет роль, а показывает текущую страницу так, как её увидит человек на
телефоне, — не сужая окно браузера и не открывая DevTools. Она
**ортогональна** режиму роли: можно быть «Учитель + телефон», «Ученик +
телефон», «Администратор + телефон».

## Как это устроить — iframe, не CSS

Вёрстка отзывчива по **ширине окна** (`md:`, `lg:` — media queries).
Сузить контейнер внутри страницы не поможет: media queries смотрят на
viewport, и «телефонная» вёрстка не включится; переписывать все `md:` на
container queries — не вариант. Поэтому мобильный вид — это **iframe
390×844 с тем же приложением** внутри: у iframe свой viewport, и вся
вёрстка переключается сама, честно, включая сайдбар-«шторку», нижние
панели, шаг-ленту задач §175 — всё, что снимается на харнессе 390×844.

Один origin → сессия Supabase (localStorage) и режим роли
(`staffModeStore`, ключ на profile_id) внутри iframe **те же**. Ничего
не подменяется, никаких новых прав: iframe — это просто второе окно того
же приложения тем же человеком.

### 1. Состояние

В `staffModeStore` — **отдельное** поле `mobilePreview: boolean`
(не четвёртый `StaffMode`: режимов роли по-прежнему три, «телефон» —
переключатель поверх). Сохраняется в `localStorage` тем же ключом на
profile_id, что и режим (расширить сохраняемую структуру, старое
значение-строка читать как раньше — не сломать уже сохранённый режим).
Хук `useMobilePreview()` → `{ enabled, setEnabled }`; включать могут
только `canSwitchStaffMode(role)` — для остальных всегда `false`.

**Внутри iframe** переключатель показывать нельзя (иначе iframe в
iframe). Признак «я во вложенном окне» — `window.self !== window.top`
**и** `search`-параметр `?mobile-preview=1` в адресе iframe (оба сразу;
один `self !== top` — ложные срабатывания в чужих встраиваниях). Внутри:
кнопка «Телефон» не рисуется, `mobilePreview` считается `false`, и
никакой iframe не создаётся. Вынести признак в `isInsideMobilePreview()`
рядом со стором.

### 2. Оболочка

Новый компонент `MobilePreviewFrame` в `components/layout/`. Когда
`mobilePreview` включён (и мы не внутри iframe), `DashboardLayout`
**вместо** обычного дерева (сайдбар, шапка, `<main>`) рисует:

- тёмно-серый фон на всё окно;
- сверху полоса на всю ширину: иконка телефона, «Мобильный вид · 390×844
  · экран как на телефоне», справа кнопка **«Выйти из мобильного вида»**
  (`data-testid="mobile-preview-exit"`); полоса **не** желтая — жёлтая
  занята предпросмотром ученика (§178), эту сделать тёмной (slate-900,
  белый текст);
- по центру — «телефон»: рамка со скруглением 40px, тёмная обводка, внутри
  `<iframe src={currentUrl + '?mobile-preview=1'} width=390 height=844
  title="Мобильный вид">`, где `currentUrl` — `location.pathname +
  location.search + location.hash` внешнего окна на момент включения.
  На экранах ниже 900px по высоте — масштабировать рамку `transform:
  scale(...)` так, чтобы телефон помещался целиком (оболочка сама должна
  влезать в ноутбук 1280×720).

**Адрес синхронизируется в обе стороны, минимально:** при навигации
внутри iframe внешний адрес обновлять (`history.replaceState`) —
слушать `load` iframe и, поскольку origin один, читать
`iframe.contentWindow.location` по таймеру 500 мс или по событию
`popstate` через `contentWindow.addEventListener` после загрузки. Тогда
«Выйти из мобильного вида» возвращает **в тот же экран**, куда человек
дошёл на «телефоне», а обновление страницы (F5) — снова показывает
телефон на нужном адресе. Обратное направление (внешние ссылки во время
мобильного вида) не нужно: внешней навигации в этом состоянии нет —
всё дерево заменено рамкой.

`StudentPreviewBanner` (§178) внутри iframe рисуется как обычно — у
«Ученик + телефон» будет жёлтая полоса внутри телефона, это правильно.

### 3. Кнопка

В `StaffModeSwitch` — справа от трёх режимов, через тонкий разделитель,
кнопка-иконка `Smartphone` (lucide) с `aria-pressed`, `title`
«Мобильный вид», `data-testid="staff-mode-mobile"`. Визуально в той же
группе (как просил владелец — «такая же плашечка»), но это переключатель,
а не режим: нажатие не меняет `mode`. В самой группе на узких экранах
(`md:hidden` шапки) кнопку не показывать — на телефоне мобильный вид
бессмыслен.

### 4. Что не делать

- Не добавлять четвёртый `StaffMode`, не трогать `effectiveRoleOf`,
  `isPreviewMode`, `RoleGuard`, роутинг.
- Не подменять `navigator.userAgent`, не эмулировать touch — только
  ширина viewport.
- Не второй размер (планшет) — если захочется, это одна константа; сейчас
  только 390×844.
- `components/demo/*`, `lib/demo.ts` не трогать.

## Приёмка

- Тесты (vitest, поведенческие): кнопка видна только admin/owner; нажатие
  включает `mobilePreview`, `mode` не меняется; в `DashboardLayout` при
  включённом режиме есть `iframe[title="Мобильный вид"]` с `src`,
  содержащим текущий путь и `mobile-preview=1`, а сайдбара/шапки нет;
  «Выйти» выключает и возвращает обычное дерево на адресе iframe;
  `isInsideMobilePreview()` = true → кнопка не рисуется и iframe не
  создаётся при любом состоянии стора; старое строковое значение в
  `localStorage` читается как режим без ошибок.
- Харнесс: сцена — владелец, 1280×800: тема курса в мобильном виде
  (виден телефон с шапкой-«бургером» внутри); та же сцена в режиме
  «Ученик + телефон» (жёлтая полоса внутри телефона). В
  `../patches/034-shots/`. Внутри iframe харнессу ничего дополнительно
  не нужно: адрес тот же `localhost:5199`, перехват запросов работает и
  для вложенных окон (проверь; если Playwright не перехватывает
  запросы iframe — `context.route` на контексте, не на странице).
- `npx tsc -b > tsc.log 2>&1; echo $?` последним; патч от `origin/main`,
  `../patches/034-mobile-preview.patch`; отчёт.
