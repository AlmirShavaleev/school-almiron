# 045 · Находка ИИ знает своё задание

**Статус:** новая
**Кому:** облачный агент оркестратора
**Ветка:** `work/ai-finding-task`, от `origin/main`
**Раздел PROJECT_STATE:** **§192** — номер выдан оркестратором
**Заведено:** 2026-09-16

## Зачем

§186 показал таблицу по заданиям в панели проверки, и клик по неверной
строке подсвечивает находку. Но связь между строкой и находкой сейчас
**восстанавливается из текста**: `taskNoFromText` ищет «В задаче 4…»,
«задание 12», «№ 7». Модель пишет номер в текст почти всегда — но
«почти».

При этом сам номер у функции **уже есть**: `filterFindings`
(`findings.ts`, §180) принимает у находки поле `task` и по нему держит
лимит «одна находка на задание». Он просто никуда не сохраняется:
в `topic_homework_ai_findings` такого столбца нет (проверено по
миграции `20260730225053`).

То есть надёжная связь стоит: один столбец, одна строка в `index.ts` и
переход панели с догадки на данные.

## Что сделать

### 1. Миграция (только файл, не применять)

`supabase/migrations/PENDING_192.sql`:

```sql
alter table public.topic_homework_ai_findings
  add column if not exists task text;
comment on column public.topic_homework_ai_findings.task is
  'Номер задания, к которому относится находка (v18+, §192). …';
```

Только добавляющее. Применяет оркестратор через MCP, он же переименует
файл по фактической версии.

### 2. Функция

В `index.ts`, там где собираются `rows` для вставки в
`topic_homework_ai_findings`, добавить `task: f.task || null`. Значение
уже посчитано (`FindingDraft.task`), ничего вычислять не надо.

Если столбца на проде ещё нет, вставка упадёт целиком — а с §180 ошибка
записи честно роняет задачу в `failed`. Поэтому **порядок обязателен:
сначала миграция, потом деплой**; написать это в отчёте явно.

### 3. Панель

`aiHomeworkCheck.ts`: `findingsOfTask` сначала смотрит на поле `task`
находки, и только если оно пустое (старые проверки) — на текст, как
сейчас. Правило одно, в одном месте; в панели ничего не переделывать.
Тип `AiFindingRow` дополнить полем `task?: string | null`.
`src/types/database.ts` **не перегенерировать** — дописать столбец
руками в три места (`Row`/`Insert`/`Update`), как это сделано для
`tasks`/`dropped_findings` в §180.1: полная регенерация тянет поломку в
чужой зоне (`useStudyPlanBoard`).

## Границы

- Промпт, расчёт балла, сверку вердиктов (§189) не трогать.
- Функцию не деплоить — деплой оркестратора после слияния и миграции.
- Панель: только источник связи, никакой новой разметки.

## Приёмка

- Тесты: находка с полем `task` привязывается к строке даже если в
  тексте номера нет; находка без поля — по тексту (старое поведение
  сохранено); находка без того и другого не привязывается ни к какой
  строке и не ломает панель.
- `npx tsc -b > tsc.log 2>&1; echo $?` последним; патч от `origin/main`
  в `../patches/045-ai-finding-task.patch`; отчёт с порядком выката
  (миграция → деплой).
