# 011 · Привязка Telegram с телефона не открывает бота

**Статус:** принято
**Кому:** чат Telegram-уведомлений (зона §142 — мастер привязки)
**Ветка:** `work/tg-link-mobile`, от свежего `main`
**Раздел PROJECT_STATE:** **§157** — номер выдан оркестратором
**Заведено:** 2026-09-12

## Симптом

Хайруллин Даниль (профиль `0c430ec6-…`) нажал «Привязать» сегодня в
09:41 по Москве. Токен создан (`telegram_link_tokens`, срок час), но
не использован; в `telegram_connections` строки нет; **вебхук бота за
это время не вызывался ни разу** — Telegram не получил `/start`.

Это не один Даниль. Сверено по базе за две недели:

| Период | Ссылок создано | Привязок состоялось |
|---|---|---|
| 03–07.09 (старый экран) | 23 | **23** |
| 08–12.09 (после §142) | 10 | **2** |

Со 100 % до 20 % ровно в день, когда в `main` вошёл мастер привязки.

## Причина — по коду, не по догадке

`src/components/shared/TelegramOnboarding.tsx`, `handleConnect`:

```ts
const url = await requestTelegramLink()
window.open(url, '_blank', 'noopener,noreferrer')
```

`window.open` вызывается **после `await`** — то есть уже не внутри
касания пользователя. Мобильные браузеры (Safari на iPhone всегда,
Chrome на Android часто) считают такое окно всплывающим и **молча
блокируют**. Человек нажал кнопку, увидел «Ждём подтверждения…», а
Telegram не открылся. Токен при этом создан — отсюда и картина в базе.

На компьютере блокировщик мягче, поэтому две привязки за неделю
прошли, и никто не заметил.

Страница настроек (`SettingsPage.tsx`, строка ~791) делает иначе:
после создания ссылки показывает **настоящую ссылку `<a href>`**, на
которую человек нажимает сам, плюс подсказку с командой `/start …`.
Этот путь работает — его и надо взять за образец.

## Что сделать

Цель: **нажатие «Привязать» на телефоне приводит в бота.** Способ на
твой выбор, два рабочих:

- после создания ссылки показывать кнопку-ссылку «Открыть Telegram»
  (`<a href={url} target="_blank">`) прямо в карточке, плюс команду
  `/start <token>` как запасной путь — ровно как в настройках, лучше
  одним общим компонентом, чтобы не было двух копий;
- либо открывать окно **синхронно** в момент клика (`window.open('')`
  до `await`) и подставлять адрес после — работает, но хрупче и хуже
  читается.

Первое предпочтительнее: одна механика в двух местах вместо двух.

`startCommandFor` уже есть в `telegramLinkApi.ts` — используй.

## Приёмка

- в тесте карточки: после нажатия появляется ссылка с адресом из
  ответа функции и команда `/start`; `window.open` после `await` в
  файле отсутствует;
- скриншот карточки на 390 после нажатия;
- владелец проверит живьём с телефона на превью — единственная
  настоящая проверка для блокировщика всплывающих окон.

**Одна доработка до слияния: нет раздела §157 в `PROJECT_STATE.md`.**
Хвост файла — §155, твоего раздела нет. Номер выдан в задаче, правило

`TelegramOnboarding`, не узнает, почему там ссылка вместо окна. Коротко:
симптом (100 % → 20 % привязок с 08.09), причина (окно после `await`),
решение (общий компонент), что проверить живьём. Заодно сообщение
коммита — по нашему образцу, с номером: `§157: …`.

**И замечание по процессу, не по коду.** В ходе работы ты пытался войти
на dev-сервере «демо-учеником». Учётные записи — владельца, учеников,

`РАБОЧИЙ_ПРОЦЕСС.md`. Что вход не прошёл из-за сети — не оправдание,
