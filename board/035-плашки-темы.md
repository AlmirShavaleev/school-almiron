# 035 · Тема в списке курса: вместо перечня рубрик — три сигнала «что делать»

**Статус:** новая
**Кому:** облачный агент оркестратора
**Ветка:** `work/topic-row-signals`, от `origin/main` (`d7369cd` — §149, §180, §181 уже слиты владельцем)
**Раздел PROJECT_STATE:** **§182** — номер выдан оркестратором
**Заведено:** 2026-09-15

## Просьба владельца

Скриншот раздела «Механика» (53 темы, `StudentCoursePage`, вид «Список»):
под каждой темой шесть-семь плашек рубрик — «Конспект», «Задачи»,
«Рабочий лист задач», «ДЗ», «Решение ДЗ», «Рабочий лист ДЗ» — в две
строки. Слова владельца: «Давай вокруг одной темы оставим только важные
элементы. Например: Видео, есть ДЗ, решение ДЗ открыто, 7 задач».

Согласовано в переписке (владелец выбрал):

1. Под названием — **три сигнала**: «Видео», «Задачи N из M», состояние
   ДЗ. Остальные рубрики — одной серой строкой «ещё 4 материала», без
   перечисления.
2. Правая плашка статуса — **только значимое**: «На проверке»,
   «Доработать», «Пройдено», «Закрыта». «В работе» (= ученик просто ещё
   ничего не делал) **убрать** — она стоит у всех тем и потому не значит
   ничего.

## Почему так, а не «свернуть лишние плашки»

Плашки отвечают на вопрос «что внутри темы», а ученик на этом экране
решает «что мне здесь делать и сколько осталось». Поэтому: рубрика без
состояния (есть конспект / есть рабочий лист) — это содержимое, оно и так
видно при открытии темы; а «решено 3 из 7» и «ДЗ не сдано» — действие.

## Что сделать

### 1. Сигналы под названием темы (`TopicListRow` и карточка `TopicCard`)

Ровно три места, в этом порядке, всё — в одну строку, `flex-wrap`:

- **Видео** — если `topic.sections.has('video')`. Иконка `Play`, подпись
  «Видео». Смысл: в теме есть видеоурок.
- **Задачи N из M** — если у темы есть задачи к уроку (M > 0). N —
  закрытые учеником (та же логика, что в ленте §175/§176: `closed_by`
  не null). При N = M — зелёная, иначе нейтральная. При N = 0 — «Задачи:
  7» без «0 из».
- **ДЗ** — если `topic.hw_id`: «ДЗ не сдано» / «ДЗ на проверке» /
  «ДЗ: 18/20 б» (принято, если есть балл; иначе «ДЗ принято») /
  «ДЗ вернули». Цвет — из уже существующего `LIST_STATE` (не заводить
  вторую палитру).
- **Ещё N материалов** — серым, если остались непоказанные заполненные
  рубрики (`theory`, `notes`, `tasks`, `task_solution`,
  `worksheet_tasks`, `worksheet_homework`, `solution`, `test`). Не
  кликается, не перечисляет. Если таких рубрик нет — строки нет.

`SECTION_CONFIG`/`SECTION_STYLE` в `StudentCoursePage` после этого нужны
только для «ещё N» (счёт) — лишнее убрать, но **`TOPIC_SECTION_ORDER` и
`TOPIC_SECTION_LABELS` в `lib/topicMaterialItems.ts` не трогать**: их
читают экраны преподавателя (§100 — общий источник, второй копии не
заводить).

Про `solution` («Решение ДЗ») отдельно: сейчас плашка сообщает ученику,
что разбор существует, хотя сам разбор закрыт до сдачи
(`GATED_SECTION = 'solution'`, `TopicPage` рисует замок). Плашки больше
нет — и хорошо: обещание «решение есть» до сдачи ДЗ подталкивает списать.
Внутрь темы (замок, условие открытия) не лезем — там всё правильно.

### 2. Правая плашка статуса

В `LIST_STATE` (и в карточке) `not_started.statusLabel` → `null`, то есть
плашка не рисуется; цвет строки и иконка остаются как есть. Остальные
состояния не трогать. Кнопка «Сдать ДЗ» остаётся — она и есть призыв к
действию для этого состояния.

### 3. Откуда брать «N из M» — новая RPC

В `useStudentCourseProgram` данных о задачах нет. Нужна **одна** RPC на
курс (не запрос на тему — тем бывает 170):

```
course_topic_tasks_progress_for_student(p_course_id uuid)
  returns table (topic_id uuid, tasks_total int, closed int)
```

— `language sql`, `stable`, `security definer`, `set search_path to ''`,
`revoke from public, anon`, `grant execute to authenticated`. Считать
**той же формулой**, что `topic_task_progress_for_staff` (§164) и
`course_topic_tasks_matrix` (§174): всего — по варианту-носителю
(`test_variants.topic_id`), закрыто — по `closed_by is not null` у строк
**вызывающего ученика**. Иначе число в ленте темы и в списке разойдутся,
и владелец это увидит первым.

Права: строки только по курсам, где вызывающий — ученик
(`group_students` → `groups.course_id`), у персонала — ноль строк
(им этот экран не нужен: в предпросмотре §178 прогресс честно пустой).
Темы без задач не возвращать.

SQL — в `supabase/migrations/PENDING_182.sql`, **не применять**:
применяет оркестратор через MCP, он же переименует файл.

В хуке: после загрузки тем — один вызов RPC, разложить в
`Map<topic_id, {total, closed}>`, положить в `TopicProgress` поля
`tasks_total: number` и `tasks_closed: number` (по умолчанию 0).
**В предпросмотре (`usePreviewMode()`) RPC не звать вовсе** — как и
попытки ДЗ (комментарий в шапке хука): персоналу она вернёт ноль строк,
и в предпросмотре будет «Задачи: 7» без прогресса. Это правильно.

Если RPC ещё нет на проде (миграция не применена), хук должен пережить
ошибку: `console.warn` и пустая карта, экран рисуется без «N из M».
Иначе список курса упадёт у всех между слиянием и применением миграции.

## Границы

- Вид «Карточки» — те же три сигнала, тем же компонентом. Не рисовать в
  карточке отдельный набор.
- `TopicPage`, лента задач §175, замок разбора — не трогать.
- Экраны преподавателя (`Материалы`, матрица §174) — не трогать.
- Легаси-плашки в других местах (поиск по `SECTION_STYLE`) не переделывать.
