# 051 · Таблица проверки: преподаватель правит, ученик видит, экран разгружен

**Статус:** новая
**Кому:** облачный агент оркестратора
**Ветка:** `work/review-task-table`, от `origin/main`
**Раздел PROJECT_STATE:** **§199** — номер выдан оркестратором
**Заведено:** 2026-09-17

## Слова владельца

Два про одно и то же место — карточку проверки работы:

1. «Таблица, которую он создаёт, не редактируется; нужна она, наверное,
   как отдельная сущность (таблица), в которую вписываются комментарии,
   если есть ошибки, и которые можно менять как выпадающее окно».
2. «Сейчас слишком перегружен экран проверки, слишком много
   дублирующейся информации».

Решения владельца по развилкам (спрошено 17.09): **таблицу после
проверки видит ученик**; с экрана убрать всё четыре пункта разгрузки
(ниже).

## Почему это не «сделать поля редактируемыми»

Сегодня таблица живёт в `topic_homework_ai_jobs.tasks` — это **ответ
модели**, слепок того, что она увидела (§180). Править его нельзя: он
нужен как есть для сравнения версий ИИ-проверки и для счётчика
выдумок. Значит таблица преподавателя — **вторая, своя** сущность:
рождается копией таблицы ИИ, дальше живёт сама, и именно она становится
результатом проверки.

## Что сделать

### 1. Миграция (`supabase/migrations/PENDING_199.sql`, не применять)

Новая таблица — на **попытку**, а не на job ИИ: это вердикт человека, и
он не должен исчезать при повторной ИИ-проверке.

```
topic_homework_review_tasks (
  id uuid pk,
  attempt_id uuid not null → topic_homework_attempts,
  no text not null,               -- номер задания, как в работе
  verdict text not null,          -- correct | wrong | partial | unchecked
  student_answer text,
  expected_answer text,
  note text,                      -- заметка преподавателя (она же уезжает ученику)
  position integer not null,
  updated_by uuid → profiles,
  updated_at timestamptz default now(),
  unique (attempt_id, no)
)
```

RLS: читать и писать — персонал курса (та же проверка, что у
`topic_homework_attempt_can_review`); **ученик читает свои строки только
после того, как по попытке есть вердикт** (есть строка в
`topic_homework_reviews`) — до проверки таблицы он видеть не должен, там
ещё черновик. Правило прописать в политике, а не в клиенте.

Плюс RPC `topic_homework_review_tasks_seed(p_attempt_id uuid)` — создаёт
строки копией из последней завершённой ИИ-проверки этой попытки, если
строк ещё нет (идемпотентно). Чтобы преподаватель не переписывал таблицу
руками с нуля.

### 2. Экран: таблица правится

В карточке проверки (панель ИИ сейчас — `AiCheckPanel`, но с §199 это
уже не «панель ИИ», а **таблица проверки**; переименуй компонент
осмысленно):

- вердикт в строке — выпадающий список из четырёх значений (владелец
  прямо просил «как выпадающее окно»);
- заметка — редактируемое поле, одна строка с раскрытием по клику;
- ответ ученика и ожидаемый ответ — тоже правятся (ИИ читает почерк с
  ошибками, это то место, где преподаватель его исправляет);
- строку можно добавить и удалить: модель могла пропустить задание или
  выдумать лишнее;
- сохранение — сразу по изменению (как отметки в `SubmissionReviewer`,
  там это уже принято), с индикатором «Сохранено»;
- балл пересчитывается из **таблицы преподавателя** по той же формуле,
  что у ИИ (`correct + 0,5·partial` / `всего − unchecked` → шкала), и
  подставляется в поле балла вердикта. Не подменять руками введённый
  балл: если преподаватель вписал своё число, показывать рядом
  «по таблице получается N» и кнопку «взять из таблицы».

### 3. Экран: разгрузка (все четыре пункта)

- **Список находок ИИ из панели убрать** — он дословно дублирует правую
  колонку «Комментарии», где те же тексты привязаны к местам в работе
  (это же спрашивал агент §186 в своём отчёте).
- **Длинные заметки в таблице свернуть** до одной строки, полная — по
  клику.
- **Резюме ИИ свернуть по умолчанию** под заголовок со счётчиками; при
  раскрытии — как сейчас, с кнопкой «Вставить в комментарий».
- **Похвалы в правой колонке спрятать под переключатель** «показывать
  похвалы» (по умолчанию выключен): при проверке нужны ошибки. Сами
  находки `praise` не удалять — ученику они полезны, речь только о виде
  экрана проверки.

### 4. Ученик видит таблицу

В разборе работы у ученика (`TopicHomeworkReview` /
`HomeworkAttemptDetailModal` — посмотри, где показывается вердикт и
комментарий) добавить блок «По заданиям» из
`topic_homework_review_tasks`: номер, вердикт значком, его ответ,
правильный ответ, заметка преподавателя. Порядок — `position`.
Если строк нет (старые работы, работы без ИИ-проверки) — блока нет
вовсе, экран как раньше.

На телефоне — не таблица, а список карточек (как в §186).

## Границы

- `topic_homework_ai_jobs.tasks` и `topic_homework_ai_findings` не
  менять: слепок ИИ остаётся как есть.
- Вердикт, балл, комментарий (`topic_homework_reviews`) — не
  переделывать; таблица их только подпитывает.
- Логику ИИ-проверки, промпт, edge-функцию не трогать.
- `SubmissionReviewer` (рамки на работе, прокрутка §184, раскладка §190)
  — не трогать, кроме переключателя похвал в списке комментариев.
- Карточка §198 («принять после доработки») правит блок вердикта в
  `HomeworkReviewQueuePage` и **не** открывает `AiCheckPanel`; ты
  наоборот: работай в панели и в ученическом разборе, а в
  `HomeworkReviewQueuePage` меняй только то, без чего панель не
  подключить. Если понадобится больше — скажи в отчёте, не делай.

## Приёмка

- SQL-пробы под ролями (в откатываемом блоке): персонал курса читает и
  пишет строки; чужой преподаватель — отказ; ученик видит свои строки
  только после вердикта, до вердикта — ноль строк; `seed` идемпотентен.
- Тесты: смена вердикта в списке пересчитывает балл и сводку;
  правка заметки сохраняется; добавление и удаление строки; «взять из
  таблицы» подставляет балл; списка находок в панели больше нет; резюме
  свёрнуто по умолчанию; переключатель похвал скрывает зелёные
  комментарии; у ученика блок появляется только при наличии строк и
  только после вердикта.
