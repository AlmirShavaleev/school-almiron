# School: исправления по нагрузочному тесту

Исходный отчёт: student-load-2026-11-16T22-26-20-951Z.json, версия v6.2-student.
При 5 активных учениках: P95 экранов 46,489 с, API 19,595 с, 8 HTTP 5xx.
Журналы за время теста подтвердили отмены 57014 в прогнозе, активности и пакетных запросах. Загрузка CPU из отчёта относится к ноутбуку; метрики CPU БД не получены.

## Изменения

- Миграция `20261116224312_reuse_forecast_evidence_and_activity_days` уже применена к School.
- Прогноз получает общий набор результатов один раз для окна, покрывающего и 180 дней истории, и окно определения зон. Границы, веса, округление и вызов catalog_zone_of сохранены. Для истории используется включённая верхняя граница, для зон — прежняя строгая граница.
- Активность один раз получает дни решения и использует их для серии и календаря. Счётчики курсов и определение выполненной темы не менялись.
- Клиент больше не повторяет все составляющие пакета после HTTP 500 / 57014. Каждый потребитель получает исходную ошибку; последующий новый запрос по-прежнему может пройти. Поведение для отсутствующей RPC (404), обрыва сети и других ошибок не изменено.
- Перед чтением course_showcase и course_unlock_modes список course_id очищается от невалидных UUID и повторов. Пустой список не отправляется. Эти два запроса дали 77 ошибок 22P02 в рассмотренном интервале; точные значения неверных параметров журналом не раскрыты. Исправление предотвращает такие запросы, но источник каждого неверного ID не установлен.
- Тест карточки курса использует настоящий формат UUID вместо условного c1, чтобы проверять путь получения режима курса.

## Проверки

- До применения новые вычисления сопоставлены с прежними для всех 98 профилей в read-only транзакциях: прогноз и активность совпали.
- При сравнении прогноза нормализован порядок свидетельств с одинаковым временем: исходный запрос не задаёт порядок при совпадении timestamp.
- После применения подтверждено совпадение ответов публичных функций под authenticated для ученика, преподавателя, куратора, администратора и отсутствующего профиля. Текущее поле now исключалось из сравнения.
- Владелец, ACL и сигнатуры функций сохранены; новые привилегированные функции не создавались.
- Локально проверены 128 тестов в 16 наборах, включая прогноз, активность, пакетные вызовы, кэш, страницы курсов и хранимый прогноз; один тест с фиктивным ID исправлен и повторно прошёл.
- Отдельно повторно прошли 27 тестов четырёх изменённых участков с файлом уже применённой миграции.
- Проверка типов прошла.
- Новые SQL-тесты подтверждают сокращение сбора свидетельств и дней с двух вызовов до одного; проверяют окно >180 дней, границы дат, пустые/длинные массивы номеров, будущие результаты, личность ученика, серии и гостевой отказ.

## Замеры

Семь чередующихся последовательных прогонов прежних и новых SQL-расчётов, одинаковые данные и auth-контекст в одной read-only транзакции:

| Расчёт | Медиана до | Медиана после |
|---|---:|---:|
| Прогноз | 24,657 мс | 16,089 мс |
| Активность | 17,322 мс | 15,572 мс |

Это внутренние расчёты, без HTTP и ожидания соединения. Небольшой выигрыш активности не объясняет и не устраняет сам по себе задержки в десятки секунд. Снижение перегрузки за счёт прекращения повторов требуется подтвердить новым нагрузочным прогоном после выкладки клиента.

## Выкатка и откат

Миграция действует в School сразу; повторно её применять не нужно. Изменения клиента вступают в силу после слияния и успешного развёртывания Vercel.
Для отката только SQL этого этапа: rollback_school_forecast_activity.sql как новая миграция. Для отмены клиента — откат коммита GitHub. Миграции предыдущих этапов сохраняются.

Нагрузочный тест рабочей БД в этой работе не запускался.
