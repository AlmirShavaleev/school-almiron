# School: второй этап оптимизации чтения

Применена миграция `20261116220455_optimize_material_visibility_and_subscription_reads`.
Проект School, `kthfozyfruorwjhvvsbw`. Данные, тариф и расписания не изменялись.

## Что изменено

- `student_tmi_solution_topics`: флаг аварийного режима проверяется один раз; принятые работы текущего ученика собираются одним запросом, затем сопоставляются с доступными ему темами. Убрана цепочка отдельных проверок решения для каждой темы.
- `student_tmi_condition_topics`: обычные уроки определяются напрямую по уже прочитанному виду темы. Для проверочных и контрольных используется прежняя функция проверки времени открытия и сдачи.
- `my_subscriptions`: ID ученика вычисляется один раз на запрос. Состав и порядок подписок, платежи, промокоды и условия доступа сохранены.
- Политики RLS, сигнатуры, владельцы функций, search_path и права выполнения не менялись. Существующий SECURITY DEFINER сохранён, новые привилегированные функции не создавались.

## Проверки

До применения в транзакциях только для чтения сравнили прежние и новые вычисления для всех **98 профилей**: наборы тем с открытыми решениями, наборы тем с открытыми условиями и полные JSON-ответы подписок совпали.

После применения под ролью authenticated повторно сравнили материалы (количество и контрольная сумма отсортированных ID), решения, условия и подписки для ученика, преподавателя, куратора, администратора и отсутствующего профиля. Все сравнения совпали.

Локально **83 теста в 6 наборах прошли**, проверка типов прошла. Дополнительно 7 новых тестов повторно прошли с файлом уже применённой миграции. Проверены чужая принятая работа, свой черновик/сданная/возвращённая/принятая работа, аварийный флаг, отсутствие доступа к курсу, отсутствие профиля, личное время открытия, проброс прав через функции без доступа к исходным таблицам, платежи и промокоды.

Проверки Supabase повторены: категории и количество предупреждений не изменились. Владелец и ACL каждой из трёх функций совпали с исходными.

## Замеры

Замеры выполнены последовательно, без параллельной нагрузки на рабочую БД.

| Участок | До | После |
|---|---:|---:|
| SQL расчёта доступа к решениям, медиана 7 чередующихся прогонов в одной транзакции | 38,233 мс | 3,124 мс |
| SQL расчёта доступа к условиям, тот же сценарий | 26,390 мс | 3,800 мс |
| SQL чтения подписок, тот же сценарий | 0,402 мс | 0,383 мс |

| Обращения этого запроса к блокам в кеше | 8991 | 4101 |

Первые три строки измеряют тела SQL-функций с тем же auth-контекстом и привилегиями, без HTTP, сети и ожидания соединения. Для подписок заметного выигрыша в установившемся режиме на текущем небольшом объёме не заявляется.

Первые отдельные вызовы функций после замены включали построение планов и давали большой разброс; они не использованы для оценки ускорения внутренних проверок. Показатель всей страницы и её p95 под нагрузкой пока не измерены. Число поддерживаемых одновременных учеников не определено.
