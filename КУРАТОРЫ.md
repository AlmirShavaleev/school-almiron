# Кураторы: назначение поверх аккаунта — вводная для отдельного чата

От владельца через оркестратора, 2026-08-04. Читать ПЕРВЫМИ: `CLAUDE.md`
и `ОРКЕСТРАЦИЯ.md`. Новая зона: кураторство и его права.

## Решения владельца (04.08, не пересматривать)

1. **Куратор — не роль, а назначение.** Регистрация остаётся одна —
   учеником (это правильно и не меняется). Учителей заводит владелец в
   админке. Кураторство назначается ПОВЕРХ существующего аккаунта:
   владелец или учитель курса назначает любого ученика (или любой
   профиль) куратором СВОЕГО курса. Ученик 11 класса может курировать
   8 класс, оставаясь учеником в своих курсах.
2. **Права куратора на первом шаге — проверка ДЗ + просмотр:** видит
   сданные работы своего курса и ставит вердикты (принято/на доработку,
   балл, комментарий), видит программу курса и список учеников курса.
   НЕ меняет программу, НЕ открывает темы, НЕ выдаёт тесты, НЕ управляет
   составом. Расширение прав — потом, отдельными решениями.
3. Повод-жалоба: владелец пытался пригласить ученика куратором в группу —
   «роль не подходит». После этой работы такой отказ должен исчезнуть:
   назначение куратором не смотрит на роль профиля.

## Рамка (детали твои)

- **Назначение:** кнопка в курсе (страница курса/учеников) — «Назначить
  куратора», выбор из профилей; снятие там же. Писать в course_curators.
  Право назначать: владелец курса и admin.
- **Доступы через RLS/definer:** проверка «куратор этого курса» — по
  course_curators. НЕ раздавать через профильную роль. Помни закон
  «один курс = одна группа» — курс и группа взаимно однозначны.
- **Проверка ДЗ:** страница «Проверка ДЗ» (§82, зона проверки ДЗ) сужает
  выборку по useMyTeachingScope — куратору нужен вход туда со своим
  курсом. Правку самой страницы согласуй через оркестратора с зоной
  проверки ДЗ; лучше расширь scope-модуль, не страницу.
- **RPC вердикта** `topic_homework_review_attempt` — проверь, кого
  пускает; куратора курса надо впустить, чужих — нет.
- **Интерфейс куратора:** ученик-куратор входит как ученик; ему нужен
  видимый вход в кураторство (пункт меню/раздел «Курирую»), не полный
  учительский кабинет.
- **Уведомления** (notification_queue, telegram) — чужая зона: если
  куратору положены карточки о сдачах — НЕ делай сам, сообщи
  оркестратору.

## Порядок

1. Сначала разведка (таблицы, политики, «роль не подходит» — где именно
   отказ) и КОРОТКИЙ план владельцу через оркестратора: где кнопка, что
   видит куратор, какие миграции. Потом код.
2. Миграции — только MCP `apply_migration` + файл с точным именем версии;
   правки схемы → перегенерация типов в том же заходе.
3. Номер раздела — последний `## §N` в файле + 1 в момент записи
   (`grep '^## §' PROJECT_STATE.md | tail -3`); сейчас хвост в районе
   §84 — проверь сам.
4. Полный `npx tsc --noEmit > log 2>&1; echo $?` (без head), vite build,
   точечные vitest. Пробы прав — под `set role authenticated`, отказ
   должен быть виден ошибкой, не пустотой (уроки §47/§54).
5. `git status` до и после; пушит владелец. Отчёт — оркестратору.
