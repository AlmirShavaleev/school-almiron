# Тесты на темах курса из каталога — вводная

Чату тестов, от владельца через оркестратора, 2026-08-09. Читать после
`CLAUDE.md`, `ОРКЕСТРАЦИЯ.md`, `ТЕСТЫ.md`.

## Задача

У владельца собран курс «Физика ЕГЭ Шаблон» — 169 тем. Он хочет, чтобы к
темам сами прикреплялись тесты, собранные из каталога по смыслу темы:
условно «тема первой части → 10 задач первой части».

## Факты (сверены оркестратором по проду 09.08)

| | |
|---|---|
| Тем в курсе «Физика ЕГЭ Шаблон» | **169** |
| Тем в каталоге, физика ЕГЭ | **803** |
| Связь «тема курса ↔ тема каталога» | **в схеме нет вообще** |
| Физика ЕГЭ, часть 1 | 2775 задач, **все автопроверяемые** |
| Физика ЕГЭ, часть 2 | 611 задач, автопроверяемых **0** |

Вторая часть — развёрнутые решения, сравнивать со строкой ответа нечего.
Тест из них система оценить не может в принципе.

## Решения владельца (09.08)

1. **Тесты собираются только из первой части.** Вторая часть в тесты не
   идёт: из неё позже будут собираться ДЗ с ИИ-проверкой (ученик решает
   на листе, фотографирует, разбирает `check-homework-ai`) — это
   отдельная работа, здесь её НЕ делать, только не мешать ей.
2. **Сопоставление тем — автомат плюс проверка владельца.** Система
   предлагает соответствие по названиям, владелец прощёлкивает список и
   правит промахи. Час его работы на курс — приемлемая цена; молча
   доверять автомату нельзя, промах даст тест не по теме.

## Рамка (детали твои)

- **Связь** — новая таблица вида `topic_catalog_topics(topic_id,
  catalog_topic_id)`, одна тема курса может ссылаться на несколько тем
  каталога (тема урока шире темы каталога). Правит персонал курса,
  читают все, кому видна тема.
- **Экран сопоставления** — список тем курса с предложенным
  соответствием, поиск по каталогу, подтвердить/поправить/очистить.
  Обязательно видно, сколько задач найдётся по выбранной связке: связь
  без задач бесполезна, и владелец должен это видеть сразу, а не после
  сборки.
- **Массовая сборка** — «собрать тесты по всем темам курса»: для каждой
  темы с подтверждённой связью собрать вариант из N задач первой части
  (N по умолчанию 10, владелец меняет) и привязать к теме. Привязка =
  выдача (§58) — не изобретай второй механизм.
- **Идемпотентность:** повторный запуск не плодит вторые тесты у тем, у
  которых он уже есть; «пересобрать» — только явным действием.
- **Переиспользуй существующее:** сэмплер и фильтры автосборки (§52,
  §56), правило автопроверяемости `variant_answer_is_auto_checkable`
  (§62/§66/§96), выдачу §58. Никаких вторых копий правил.
- **Честность по остаткам:** если по теме нашлось меньше задач, чем
  просят, — сказать это в отчёте сборки по каждой теме, а не добить чем
  попало (правило из `ТЕСТЫ.md`).
- Каталог — читаешь, не правишь. Через оркестратора, если нужна правка
  данных.

## Порядок

Короткий план оркестратору ДО кода: устройство связи, как считается
предложение по названиям, как выглядит экран, что делает массовая
сборка. Миграции — MCP `apply_migration` + файл с точным именем, типы
MCP (не руками, §75). Номер — хвост+1 в момент записи. Полный
`npx tsc --noEmit > log 2>&1; echo $?` **буквально последним действием**,
тест каждого меняемого файла. Отчёт оркестратору.
