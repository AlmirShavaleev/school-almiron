# Упрощение: один курс = одна группа

Решение владельца, 2026-08-03, продуктовый закон проекта: **один курс — одна
группа** (в ней может быть и один ученик). Новый поток = копия курса с новыми
датами и новым приглашением. Многогрупповость внутри курса упраздняется как
понятие; группа остаётся во внутренней схеме как техническая сущность, за
которую держатся занятия, журнал и посещаемость.

Читать после `CLAUDE.md` и `ОРКЕСТРАЦИЯ.md`. Выполнять ПОСЛЕ тумблера тем —
обе работы в контуре курса, эта вторая.

## Состояние данных (прод, 2026-08-03, сверено оркестратором)

## Порядок работы

### 1. Уборка данных (миграция, до ограничения)

- «10А»: оставить одну группу (по смыслу — «10 А Лицей Альметьевск»), три
  пустые снести. Перед сносом проверить ссылки: `group_students`, `lessons`,
  `subscriptions`, `test_variant_assignments`/`sync_group_assignment`,
  посещаемость, всё, что найдёшь по FK. Пустота по таблице выше — не
  гарантия пустоты по всем ссылкам.
- «11А 2026-2027»: слить две группы в одну (обоих учеников — в оставшуюся),
  вторую снести. Какую оставить — по названию курса.
- Откат: снимок затронутых строк по образцу каталога (§50).

### 2. Ограничение и автосоздание

- `unique` на `groups.course_id`. Это заодно НАВСЕГДА закрывает гонку §21
  (два первых ученика создавали по группе) — отметь §21 закрытым в хвостах.
- Создание курса автоматически создаёт его группу (если этого ещё нет).
- `course_join_accept` и все пути вступления: только присоединение к
  СУЩЕСТВУЮЩЕЙ группе курса, никакого создания групп по факту вступления.
  Проверь и ветку кураторской ссылки, и легаси-приглашения.
- Копирование курса: копия обязана рождаться со СВОЕЙ новой пустой группой —
  проверь, что уже так; если нет — почини в копировании.

### 3. Интерфейс

- Слово «группа» уходит из интерфейса всюду, где оно = курс: управление
  группами, выборы группы в диалогах. Где выбор группы обязателен технически
  (выдача варианта, назначение ДЗ) — группа подставляется сама, диалог её не
  спрашивает.
- Журнал, посещаемость, занятия — работают как раньше (они держатся за
  group_id, который теперь один на курс).

### 4. Координация (через оркестратора)

- Чат тестов строит диалог выдачи с галочками групп — после этой работы
  диалог должен вырождаться в «без вопроса про группы». Не переделывай его
  сам — сообщи оркестратору, он передаст тестам.
- RLS и права не перелопачивать: `course_is_staff` и групповые проверки
  остаются как есть — они не мешают модели 1:1.

## Границы

Полный вынос групп из схемы НЕ делать — за `group_id` держится половина базы.
Это упрощение продукта, не перелом хранения. Номер раздела — хвост+1 в момент
записи (`grep '^## §' PROJECT_STATE.md | tail -3`). Миграции — только
`apply_migration` + файл с точным именем. Типы базы перегенерировать в том же
заходе. План — владельцу до кода, применение — после «да».
