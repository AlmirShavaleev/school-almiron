## Неизменные правила проекта

- Проба под `set role authenticated`, читающая ту же таблицу, что проверяет,
  умеет молча самоустраняться из-за RLS: отсутствие строки в результате — не
  «успех», а повод перечитать от владельца (урок §54).
- `notification_queue` — общая таблица: уборка тестовых строк ТОЛЬКО по
  своему deduplication_key или entity_id, никогда по event_type (урок §71:
  снесён след доставки чужой живой выдачи, риск повторной карточки).
- **`tsc --noEmit` в ЭТОМ репозитории не проверяет НИЧЕГО** (найдено чатом
  контура курса 11.08, подтверждено оркестратором по диску). Корневой
  `tsconfig.json` — это `{"files": [], "references": [app, node]}`; без `-b`
  компилятор честно проверяет пустой список и выходит с нулём. Доказано
  намеренной ошибкой: `const __probe: number = "строка"` → `--noEmit` даёт 0,
  `-b` даёт TS-ошибку и код 2.
  **Правильная команда: `npx tsc -b > log 2>&1; echo $?`** (она же
  `npm run typecheck`), буквально последним действием.
  Историческое: правило про `--noEmit` я требовал во ВСЕХ вводных с §68 —
  это была моя ошибка, а не халатность чатов. Отсюда вся серия красных
  сборок при «зелёном tsc» (§89, §93.6, §100, шесть ошибок пакета
  §101–§110, `CopyDialogs` в §113): единственной настоящей проверкой типов
  был `tsc -b` внутри `npm run build` на Vercel, то есть уже после пуша.
  Обвинения в адрес чатов по этим случаям сняты.
- `… | head` маскирует код выхода — `$?` берётся от head. Никаких конвейеров
  поверх проверки (урок §68.4).
- Прогон тестов перед отчётом обязан включать тест ТОГО файла, который
  менялся — смежность «на глаз» пропускает именно его (урок §93.6:
  правка страницы прогнана без теста самой страницы, файл упал целиком
  у соседней зоны).
- Сгенерированные типы базы — НЕ страховка: они отстают от прода, tsc
  проходит с устаревшими сигнатурами RPC (дважды: §59.7 и §75 — ручная
  дописка типов затем уронила сборку). После правки схемы сигнатуры
  проверять по проду, типы перегенерировать MCP, руками не дописывать.
