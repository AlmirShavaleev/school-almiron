## Открытые вопросы

**41-страничные PDF проверяются по 4–6 страниц** (бюджет 1100 мс CPU из
жёстких 2 с). Для настоящих ДЗ хватает; для сканов сборников — нарезка рендера
на несколько вызовов, отдельная работа по решению владельца. Число взятых
страниц плавает между прогонами — осознанный размен против 546.

**Telegram по курсу «11А» молчит по данным, а не по коду.** У Виктора
Андреева нет строки в `telegram_connections` — нужен один клик по привязке
бота (можно через вход под ним). Пока связки нет, живой канал не проверить.

**Показ привязанного тестирования на странице темы у ученика.** §58 сделал
привязку настоящей выдачей, но на самой теме ученик тест не видит — получает
через свой список тестирований. Ждёт решения владельца: показывать ли тест
вкладкой на теме (как тест банка). Рекомендация оркестратора — да.

**Три текстовых бага живут в SQL-производителях, текстом не лечатся:**
дедлайн «12.08.0020» у new_homework (год 0020 — формат даты производителя),
заголовок сдачи «тема — ДЗ · тема» (дубль), даты занятий машинным ISO.
Первые два — зона уведомлений (после «да» по текстам), variant_* — зона
тестов. Номера — хвост+1.

**Продуктовый закон (владелец, 2026-08-03): один курс = одна группа.**
Поток = копия курса. Задание `ГРУППЫ_УПРОЩЕНИЕ.md` в корне — контуру курса,
ПОСЛЕ тумблера тем: уборка шести групп двух курсов, unique на
groups.course_id (заодно закрывает гонку §21), автосоздание группы с курсом,
слово «группа» уходит из интерфейса. После внедрения диалог выдачи вариантов
у тестов вырождается — передать им через оркестратора.

**Бэклог: две строки groups нарушают валидный FK на courses.** E2E-группы
2026-07-28 ссылаются на удалённые курсы при `convalidated=true` — тихая порча
мимо ограничения, след прошлых удалений курсов. Сироты сносятся в уборке
групп; разбор «как так вышло» — отдельная задача, не про группы.

**Урок оркестратора (вторая вводная с неверными данными за сутки):** запрос
«группы по курсам» слеп к курсам без групп и считает группы удалённых
курсов. Считать связь надо с обеих сторон. Первый случай — «красные тесты»
каталога, второй — «пять курсов по одной группе» в ГРУППЫ_УПРОЩЕНИЕ.md.

**Тесты, очередь (порядок утверждён):** точка-с-запятой «все части» (25) →
«да»/«нет» точным сравнением (178, решение оркестратора 03.08) → диалог
выдачи без вопроса о группе → ISO-даты и формулировки variant_*. Пул
автосборки после §63: 15 399 (+72 нормализация, +62 «любое из»); предикат
переписан поверх variant_answer_alternatives — одно правило, не две копии.

**Каталогу (задание выдано): два следа в данных.** 57 задач «какие
утверждения истинны» — множественный выбор без partial_type, проставить его
правильнее, чем учить сравнение. И порча импорта: answer_html вида «3,80,1»
(слипшиеся «3,8»+«0,1») — расследовать масштаб.

**Продуктовый факт для владельца:** у математики уровень «сложные» в
автосборке пуст (0 задач) — вторая часть это развёрнутые решения, они
непроверяемы автоматом в принципе. Вернутся только с ручной проверкой
вариантов, если она когда-то понадобится.

**Группы: остался один хвост — идемпотентность трёх функций вступления**
(invite_student_flow, distribute_join_request, distribute_student_courses).
Ветки недостижимы по построению, закон держит база с четырёх сторон
(триггер + CASCADE + unique + NOT NULL, §61/§64); это качество сообщения в
недостижимой ветке, не дыра. Делать отдельной свежей сессией, по одной
функции за заход, с пробой «курс без группы в обход триггера → функция
дважды → одна группа, один id» — рецепт в отчёте §64.

**Бэклог «зачистка перед запуском» пополнен списком §61:** курсы «10», «dsa»,
«егэ», «Тестовый курс(+копия)», темы «пердун», «1/1/1/…», демо-аккаунты,
три PDF про грант из отладки §48.

**Бэклог: check-ограничение на topic_homework.due_at** (разумный диапазон
лет) — поле принимало год 0020. Две битые строки оркестратор обнулил руками
03.08 (тестовые данные, «Без дедлайна» печатается честно). Ограничение —
контуру ДЗ отдельной миграцией.

**Снимки отката каталога живут до просмотра владельцем.**
`catalog_topics_title_backup_20260803` (803 строки) и
`catalog_task_topics_rehang_backup_20260803` (11) — удалить отдельной
миграцией после того, как владелец посмотрит новые списки тем глазами.

**Ответы каталога видны любому вошедшему — это продукт, не дыра.** Каталог
намеренно показывает решения (самопроверка). Для тестов прямой путь закрыт
definer-RPC; остаточный риск — найти задачу теста поиском в каталоге и
списать. Продуктовое решение владельца, не срочное.

**Vercel.** Был период, когда деплой не создавался для запушенного коммита.
После каждого пуша стоит убеждаться, что сборка появилась.

2. Проверяет, не залез ли чат в чужую зону (`git status` до и после).
3. Сводит: не конфликтуют ли правки разных чатов в общих файлах.
4. Выдаёт следующий номер раздела и обновляет этот файл.

## Неизменные правила проекта

- Проба под `set role authenticated`, читающая ту же таблицу, что проверяет,
  умеет молча самоустраняться из-за RLS: отсутствие строки в результате — не
  «успех», а повод перечитать от владельца (урок §54).

- Миграции — только MCP `apply_migration`, **никогда** `supabase db push`;
  файл в `supabase/migrations/` с именем, ТОЧНО совпадающим с записью в
  `supabase_migrations.schema_migrations`.
- Пушит и деплоит владелец, не агент.
- Файлы кладутся владельцу на диск в `D:\Школа Almiron` — облачная копия
  репозитория не источник правды. После 2026-08-03 жёстче: НИКАКИХ утверждений
  о состоянии кода по облачной копии — только диск владельца или задеплоенное.
  На этом сгорели дважды: «красные тесты каталога» и обе «поломки» в
  ТГ_УВЕДОМЛЕНИЯ.md, которых в актуальном коде уже не было.
- Свою работу дописывать в `PROJECT_STATE.md` с причиной, а не перечнем
  изменений.
