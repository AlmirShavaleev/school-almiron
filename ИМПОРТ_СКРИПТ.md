# Скрипт-импортёр уроков из папки — вводная для отдельного чата

От владельца через оркестратора, 2026-08-06. Читать ПЕРВЫМИ `CLAUDE.md`
и `ОРКЕСТРАЦИЯ.md`. Смежный документ — `ИМПОРТ_МАТЕРИАЛОВ.md` (кнопка
импорта в интерфейсе): она остаётся на потом, сейчас нужен **скрипт**.

Причина выбора: 53 урока × 6 файлов = 318 PDF, ~477 МБ. Через браузер
это больно; скрипт быстрее и остаётся рабочим инструментом на весь год —
владелец добавляет уроки в папку и прогоняет его снова.

## Что делает скрипт

`npm run import-course -- --dir "<папка раздела>" --course <id|--new "Название">`

Раскладывает папку раздела в курс: раздел → модуль, `Урок NN - Название`
→ тема, шесть файлов урока → рубрики и ДЗ.

## Схема прода (проверена, не угадывай)

- `modules(id, course_id, title, order_index)`
- `topics(id, module_id, title, order_index, max_score, available_from,
  is_open)` — создавать с `is_open = false`.
- `topic_material_items(topic_id, kind, section, storage_path, file_name,
  mime_type, size_bytes, position, is_visible, created_by)`;
  `kind = 'file'`, `is_visible = true`. Поле `lesson_id` — легаси, null.
- `topic_homework(topic_id, title, instructions, is_published, created_by,
  due_at, grade_scale)` — создавать `is_published = false` (черновик).
- `topic_homework_files(homework_id, storage_path, original_filename,
  mime_type, size_bytes, position)`.
- Бакеты: материалы → **`topic-materials`**, файлы задания →
  **`topic-homework`**. Формат пути в обоих (образец с прода):
  `<topic_id>/<epochMs>_<транслит-имя>.pdf`; в `file_name` /
  `original_filename` — исходное имя как есть, кириллица допустима.
- Курс с `--new`: создать строку в `courses`; **группа появится сама**
  триггером (§61, «один курс = одна группа») — руками не создавать,
  проверить, что появилась ровно одна.

## Жёсткие требования

1. **`--dry-run` по умолчанию.** Первый запуск ничего не пишет: печатает
   план (какие модули/темы создаст, сколько файлов, что пропустит).
   Реальная запись — только с явным `--apply`.
2. **Идемпотентность.** Повторный прогон той же папки не создаёт вторых
   тем/модулей/материалов. Ключи: модуль — (курс, название), тема —
   (модуль, order_index), материал — (тема, рубрика, имя файла).
   Что делать с изменившимся файлом (заменить/пропустить) — реши и
   напиши в отчёте; по умолчанию пропуск с пометкой в итогах.
3. **Ноль уведомлений.** ДЗ создаются черновиками, `notification_queue`
   после прогона не должна получить ни одной строки — проверить
   запросом до и после, число в отчёт.
4. **Темы закрытыми** (`is_open = false`): владелец открывает по
   расписанию тумблером §59, импорт не открывает год вперёд.
5. **Отчёт по итогам**: создано модулей/тем/материалов/ДЗ, пропущено с
   причинами, время, суммарный объём. Файлы не по шаблону — списком, а
   не молча.
6. **Устойчивость к обрыву**: падение на 200-м файле не должно требовать
   начинать сначала — идемпотентность из п.2 это и обеспечивает,
   проверь её пробой (прервать и перезапустить).

## Ключи и безопасность

Скрипт берёт доступ из локального `.env` проекта (service role).
**Значение ключа не печатать ни в консоль, ни в чат, ни в отчёт.** Если
подходящего ключа в `.env` нет — не выдумывать обходов и не просить
владельца прислать ключ в чат: сообщить, что нужно добавить его в `.env`
самому, и остановиться. Скрипт кладёт в `scripts/`, в `.gitignore`
ничего не менять.

   дописывать, урок §75).
4. Номер раздела — хвост+1 в момент записи (сейчас в районе §100 —

   — дважды сборка падала на том, что «tsc был зелёный»).
5. Зона: `scripts/`, `package.json` (одна строка команды). В `src/` не
   лезть — там работает контур курса. `git status` до и после, отчёт
   оркестратору.
