# Раздел тестов — вводная для отдельного чата

Дополняет `CLAUDE.md` (общие правила: миграции, права, тесты) и
`ОРКЕСТРАЦИЯ.md` (зоны чатов, реестр разделов PROJECT_STATE) — их читать
первыми. Факты о данных ниже сняты с прода 2026-08-03.

## Задание владельца

Раздел тестов сейчас неудобен. Нужно:

1. **Вход — четыре кнопки:** ЕГЭ профильная математика, ЕГЭ физика,
   ОГЭ математика, ОГЭ физика. Проваливаешься — список тестов, которые создал
   учитель, у каждого видно, сколько человек прошло.
2. **Автосборка теста:** учитель задаёт тему, количество задач и раскладку по
   сложности (например: 3 лёгких, 5 средних, 2 сложных) → тест собирается из
   каталога сам. Задачи **без эталонного ответа не попадают никогда**.

Решения владельца (приняты 2026-08-03, не пересматривать без него):

- **Без ИИ.** Автосборка — детерминированная случайная выборка из каталога по
  фильтрам. Никаких вызовов моделей. ИИ-ввод текстом — возможный второй шаг,
  не сейчас.
- **Сложность через часть экзамена** там, где разметки нет: `exam_part = 1` ≈
  базовые, `exam_part = 2` ≈ сложные. Где `difficulty` заполнена (физика ЕГЭ)
  — использовать её.
- Делает этот чат, зона выделена (см. ниже).

## Данные каталога для сэмплера (прод, 2026-08-03)

| Предмет | Задач | С эталоном | С difficulty | С exam_part |
|---|---|---|---|---|
| Математика ЕГЭ | 9 515 | 6 308 | 0 | 9 515 |
| Математика ОГЭ | 5 972 | 5 346 | 0 | 5 972 |
| Физика ЕГЭ | 3 386 | 2 785 | 3 101 | 3 386 |
| Физика ОГЭ | 2 910 | 2 143 | 0 | 2 910 |

`difficulty` — текст: «лёгкая», «средняя», «сложная» (только физика ЕГЭ).
Темы — `catalog_task_topics` (см. `КАТАЛОГ_ЗАДАЧ.md`: поле `source`,
ИИ-дерево физики `ai_physics_v1` — для сэмплера решай осознанно, включать ли
обе таксономии в выбор темы).

Правила сэмплера:

- Фильтр всегда: `has_answer = true` и `is_published = true`.
- Уровень: `difficulty`, если есть; иначе `exam_part` (1 ≈ базовый, 2 ≈
  сложный). В интерфейсе честно показывать, какая шкала действует — у
  математики уровней два, не три.
- Если задач на запрошенную раскладку не хватает — не молчать и не добивать
  чем попало: показать «по теме X лёгких только 2 из 3» и дать выбор.
- Выборка воспроизводимая: сохранённый тест не должен меняться при
  перезаходе. Сохраняй выбранные task_id в `test_variant_items` сразу.
- Параметры сборки положи в `test_variants.settings` (jsonb уже есть) — чтобы
  «пересобрать похожий» работал.

## Осторожно

- **Ученик не должен видеть эталонный ответ до сдачи.** Проверь, как
  `test_variant_items` и запросы хуков отдают задачу ученику: `answer_html` и
  `solution_html` не должны утекать в клиент до завершения попытки. Если
  сейчас утекают — это отдельный пункт отчёта, чинить обязательно.
- RLS на `test_variant*` проверь до правок: кто видит чужие варианты, кто
  может выдавать. Приём проверки — в `CLAUDE.md` (set role authenticated).
- Каталог ты **читаешь, но не правишь**: `catalog_*` таблицы, `useCatalog.ts`,
  `src/pages/catalog/` — зона каталожного чата. Нужна правка данных каталога —
  через оркестратора.
- Кнопка «собрать через каталог» (корзина) должна остаться — автосборка
  дополняет, не заменяет.

## Порядок работы

1. Миграции — **никогда** `supabase db push`. Только MCP `apply_migration` +
   файл в `supabase/migrations/` с именем, ТОЧНО совпадающим с записью в
   `supabase_migrations.schema_migrations`.
2. Сначала план входа и сэмплера коротко владельцу (что меняешь в навигации,
   какие поля формы), потом код. Форма автосборки — это продукт, его вид
   владелец должен увидеть до реализации, хотя бы текстом.
3. Довести до зелёного: `npx tsc --noEmit`, `npx vite build`, точечные
   `vitest run` по затронутым файлам. Полный прогон в песочнице падает по
   таймауту.
4. Свою работу — в `PROJECT_STATE.md` с причиной, отчёт — оркестратору.
