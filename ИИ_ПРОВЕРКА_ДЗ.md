# ИИ-проверка домашних работ — вводная для отдельного чата

Дополняет `CLAUDE.md` (общие правила проекта) — его читать первым. Здесь только
про ИИ-проверку. Всё про состояние проверено запросами к проду 2026-08-03.

## Первое дело: PDF не рендерится в проде. Причина известна

**Симптом.** Проверка работы, сданной одним PDF, падает со статусом `failed`,
в `topic_homework_ai_jobs.last_error` лежит:

```
Не удалось прочитать ни одной страницы: pub_4656538.pdf —
не подтянулись пакеты для рендера PDF:
Module not found: https://esm.sh/@hyzyla/pdfium@2.1.13?target=deno
```

**Диагноз.** В `supabase/functions/check-homework-ai/index.ts` импорт движка
идёт через вспомогательную функцию:

```ts
async function importWithFallback(primary: string, fallback: string) {
  try { return await import(primary) }        // ← специфер ПЕРЕМЕННАЯ
  catch { return await import(fallback) }
}
```

Supabase собирает функцию в eszip **на этапе деплоя**, статически обходя
импорты. Динамический `import(primary)` с переменной статически не разбирается —
значит ни `npm:@hyzyla/pdfium`, ни `npm:imagescript` в сборку не попали. Дальше
рантайм пробует запасной адрес, но подтянуть модуль по сети из закрытого пакета
он тоже не может — отсюда `Module not found`.

То есть сломала не сама затея с PDFium, а «страховка», которую в неё добавили:
попытка сделать импорт устойчивее убила статический анализ, из-за которого
пакеты вообще попадают в сборку.

**Что делать.** Вернуть литеральные специферы, чтобы сборщик их увидел:

```ts
const [pdfium, imagescript] = await Promise.all([
  import('npm:@hyzyla/pdfium@2.1.13'),
  import('npm:imagescript@1.3.0'),
])
```

Запасной путь через `esm.sh` убрать целиком — в рантайме он всё равно не
работает. Оставить запасной путь для **wasm-бинарника** (`initPdfium` тянет
`pdfium.wasm` с jsdelivr, если движок не нашёл его рядом с пакетом) — это
отдельный механизм, и он как раз может понадобиться.

После правки: задеплоить (MCP `deploy_edge_function`), нажать проверку на любой
из трёх работ ниже и посмотреть `last_error`. Если появится «движок PDF не
запустился» — значит пакет доехал, а не завёлся wasm, и чинить надо уже
`initPdfium`.

Работы для проверки (все сданы одним PDF, статус «на проверке»):

```
fb264ef5-80d3-4a7c-98d3-9e53918b8c92   pub_4656538.pdf
e0ac51d6-6f2f-454a-b9fb-5bfe9dab5c9b   school-almiron-physics-ege-2026-07-32pdf.pdf
ad476ae9-5ec3-4b53-956e-d894c2fc0bc1   физмат школе.pdf
```

**Рендер сам по себе рабочий** — проверен локально в Deno на трёхстраничном PDF
из настоящих сканов ЕГЭ: PDFium + imagescript, 150 DPI, три страницы за 0.8 с,
рукописный текст читается уверенно. Постранично: 200 / 362 / 99 кБ JPEG. Дело
только в том, что пакеты не доезжают до рантайма.

## Как устроено

| Кусок | Где |
|---|---|
| Edge-функция | `supabase/functions/check-homework-ai/index.ts` (версия 5 в проде) |
| Заявка и права | RPC `topic_homework_ai_request_check` → `topic_homework_attempt_can_review` |
| Задачи | `topic_homework_ai_jobs`: `status`, `model`, `suggested_score`, `confidence`, `summary`, `last_error`, токены |
| Находки | `topic_homework_ai_findings`: `file_id`, `page`, `rect_*` (доли 0..1), `category`, `text` |
| Очередь у преподавателя | `src/pages/HomeworkReviewQueuePage.tsx` + `src/hooks/useQueueAiJobs.ts` |
| Разбор | `src/components/SubmissionReviewer.tsx`, перенос рамок через `importRegionsRef` |

Границы, которые двигать нельзя (продублировано в `CLAUDE.md`):

- **ИИ никогда не пишет в `topic_homework_reviews`.** Он готовит черновик;
  вердикт ставит человек. Если задача выглядит как «пусть ИИ сам примет
  работу» — это повод переспросить владельца, а не написать код.
- Рамки ИИ лежат отдельно и переносятся в `annotation_sets` только по действию
  преподавателя. Класть их туда сразу нельзя: `author_id` NOT NULL → profiles,
  страница пишется целиком, статуса «предложено» нет.
- Права проверяет база, а не функция. Своей проверки роли в функции нет
  намеренно: две независимые проверки прав неминуемо разъезжаются.

**Провайдер сменный.** `AI_MODEL` (по умолчанию
`qwen/qwen3-vl-235b-a22b-instruct`), `AI_BASE_URL` (по умолчанию OpenRouter),
`AI_API_KEY`. Смена модели или поставщика не требует передеплоя.

Учти: раздел про ИИ в `CLAUDE.md` **устарел** — там `qwen/qwen3.7-plus`,
переменная `AI_PROVIDER` и координаты по шкале 0..1000 через `boxToRect`. В
задеплоенной функции ничего этого нет, координаты — доли 0..1 без пересчёта.
Раздел стоит переписать по факту.

## Что уже сделано и работает

- Проверка запускается **из списка** работ, поштучно и пачкой; по три работы
  одновременно (`CONCURRENCY = 3`), больше упирается в лимиты провайдера.
- Статус приезжает на список одним запросом на все видимые работы, опрос раз в
  5 секунд, пока хоть одна задача в работе.
- Открытие работы автоматически переносит готовый черновик ИИ в разметку.
- Рамки можно двигать и растягивать мышью, стрелками — на пару пикселей
  (`src/lib/annotationGeometry.ts`).
- Разложение PDF по страницам: в `topic_homework_ai_findings.page` пишется
  настоящий номер страницы внутри файла, аннотатор кладёт рамку туда же без
  пересчёта координат. Лимит 10 страниц на всю работу, всё сверх — открытым
  текстом в конце разбора.

## Известные хвосты

**Балл расходится с разбором.** Модель ставила 5/5 и тут же перечисляла две
ошибки. В промпт добавлено требование согласовывать балл с находками, но на
выборке это не проверено. Проверять надо не на одной работе: нужен прогон
десятка и сравнение с эталоном.

**Есть размеченный набор для этого.** 26 настоящих работ ЕГЭ по физике со
сканами, с экспертными баллами и комментариями, плюс формулировки всех восьми
заданий — владелец приносил PDF ФИПИ, из него всё извлечено. Спроси у него
`fizika_mr_ege_2026.pdf`, он лежит в корне проекта.

**Промпт держится на двух вещах**, их не потерять при правках: модель сначала
решает задачу сама и только потом сверяет (иначе соглашается с ходом ученика и
подтверждает его же ошибку), и координаты просим долями страницы, повторяя
это дважды (пиксели — самый частый способ промахнуться мимо строки).

## Ловушки, на которых уже теряли время

- **Причину отказа нельзя глушить.** В первой версии список пропущенных
  страниц собирался, но при полном провале выбрасывался, и в панели было
  «ИИ не смог» без единого слова. Причину пришлось выяснять запросами к базе.
  Сейчас она попадает в `last_error` дословно — так и оставить.
- **`load()` в `useQueueAiJobs` сливает, а не заменяет.** Его зовут для
  подмножества строк; полная замена карты стирала значки у всех остальных
  работ, и после трёх запусков подряд значок оставался только у последнего.
- **Отказ отдаём кодом 200**, когда задача уже создана: supabase-js превращает
  не-2xx в `FunctionsHttpError` без тела, и панель показала бы «non-2xx status
  code» вместо настоящей причины.
- Проверить edge-функцию из облачной песочницы нельзя: `jsr.io` и CDN там
  закрыты, `*.supabase.co` тоже. Типы гоняются с заглушкой вместо
  `jsr:@supabase/supabase-js`, логика рендера — отдельным харнессом на Deno.
