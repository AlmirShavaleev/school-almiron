# Задачи к уроку «как в Stepik» — вводная

От владельца через оркестратора, 12.09.2026. Читать после `CLAUDE.md`,
`ОРКЕСТРАЦИЯ.md`, `РАБОЧИЙ_ПРОЦЕСС.md` и `ТЕСТЫ.md` (зона тестов —
твоя). Родня: §58/§60 (вариант на теме и выдача группам), §63
(нормализация ответов), §66 (вердикт одной функцией), §70 (вкладка
«Тестирование» темы), §141 (счётчики ученика), §151 (учебный план,
в работе), §152 (`topic_done_events` — общее «тема пройдена»).

## Что просит владелец, его словами

«Задачи к уроку, как в Stepik. Беру и подтягиваю из каталога задачи,
ученик заходит на урок и там решает. Это как раздел тестирования,
только более понятный».

## Четыре решения владельца, принятые до работы

1. **Проверка сразу, по каждой задаче.** Ввёл ответ — тут же верно /
   неверно. Это тренировка, не контрольная.
2. **Попыток сколько угодно.** Пока не решит. В журнале видно, с какой
   попытки.
3. **Решённые задачи считаются в «тема пройдена» и в недельный план.**
4. **Это не новая сущность, а переделка вкладки «Тестирование» на
   теме.** Те же варианты из каталога, привязанные к теме, — но поданы
   по-степиковски. Второго механизма рядом не будет.

**Вкладкой почти не пользовались.** Это освобождает: данных, которые
надо бережно переносить, нет. Модель при этом уже подходит: у
`test_variant_answers` есть `is_correct`, `points_earned`,
`first_answered_at` / `last_changed_at` по каждой задаче; у выдачи —
`allow_retry`, `max_attempts`, `show_solutions_after_submit`. Заводить
новые таблицы, скорее всего, не нужно — нужно изменить **когда**
считается ответ и **как** это показано.

## Что меняется

**Механика.** Сейчас: ответил на всё → «завершить» → вердикт по всему
варианту (`finalize_grading`, §66). Станет: ответ по одной задаче →
вердикт по этой задаче сразу, тем же `variant_grading_verdict` и той же
нормализацией §63 — **второй проверки ответов не заводить ни при каких
обстоятельствах**, это уже стоило нам +25 «;» и +178 да/нет. Попытки не
ограничены: неверный ответ не запирает задачу, верный — запирает
(решено). Число попыток до верного пишется — владелец хочет его видеть.

**Экран ученика.** На теме вкладка называется **«Задачи»** (не
«Тестирование»). Список задач урока сверху вниз, у каждой поле ответа и
кнопка, результат под ней; сверху «решено 3 из 7». Ничего не надо
«начинать» и «завершать» — открыл урок, решаешь. Условие из каталога
показывается как в каталоге (тот же рендер, те же картинки и таблицы
— `.tbl-wrap` и прочее оттуда, не копия).

**Экран преподавателя.** Подтянуть задачи из каталога к теме — это то,
что уже умеет привязка варианта (§58, §70). Не переделывай конструктор;
сделай так, чтобы с темы было ясно: «задач к уроку: 7, решают 12 из 16».

**Зачёт.** «Тема пройдена» живёт в **одном** определении —
`public.topic_done_events()` (§152) и его клиентский близнец
`topicDone`. Правило: если у темы есть задачи к уроку, тема пройдена
только когда они все решены; нет задач — как раньше. Меняется **оба
места одинаково**, с общим набором проверок; заводить третье
определение нельзя. Учебный план (§151) читает ту же функцию — с ним
это согласовано, ему ничего отдельно делать не надо, но предупреди в
плане, что число «пройдено» на проде после этого изменится.

## Границы

- Каталог задач, его рендер, нормализацию ответов и вердикт — не
  трогать, использовать.
- Контрольные варианты вне темы (раздел «Тесты», экзаменационные
  прогоны) — не трогать: у них остаётся «сдать целиком». Это другой
  сценарий, и он живёт отдельно; на теме его больше нет.
- Миграции добавляющие; только MCP `apply_migration` плюс файл с
  именем, точно равным версии; `supabase db push` — никогда. Если
  придётся менять поведение существующей RPC — отдельным пунктом плана.
- Страница темы ученика — общая с чатом учебного плана (`work/study-plan`
  монтирует одну строку). Назови в плане, какие файлы задеваешь.
- Телефон: 390 обязательны, поле ответа видно при клавиатуре (аудит,
  №13 — не повторять ленту на 11 000 px).
- Проверять под учеником и преподавателем на харнессе; учётные записи
  прода, включая «демо», не использовать (`board/014`).

## Приёмка

- ученик решает задачу, видит результат сразу, неверный ответ можно
  повторить, верный — задача закрыта, попытки посчитаны;
- «решено N из M» на теме и у преподавателя «решают X из Y»;
- `topic_done_events()` и `topicDone` дают одинаковый ответ на одном
  наборе данных (тест на оба);
- контрольные варианты вне темы работают как раньше (их тесты зелёные);
- сколько запросов при открытии темы с 7 задачами.
