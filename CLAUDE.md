# Инструкции для агента (Claude Code)

Читается автоматически при старте. Здесь — только то, что нельзя вывести из
кода и что дорого узнавать методом проб.

## Что это

«Школа Almiron» — платформа подготовки к ЕГЭ/ОГЭ.
Vite + React 19 + TypeScript + Tailwind, Supabase (Postgres + PostgREST + RLS +
Storage + Edge Functions), Vitest, Playwright.
Прод: **alminion.ru**, Vercel собирает автоматически из ветки `main`.

## Главные документы

| Файл | Зачем |
|---|---|
| `PROJECT_STATE.md` | **Начинать отсюда.** Хронология решений по разделам: что сделано, почему именно так, что сознательно отложено, что не проверено. Разделы §21–§31 — последняя сессия. |
| `MIGRATIONS.md` | Порядок работы с миграциями. Обязателен к прочтению перед любым изменением схемы. |
| `HOMEWORK_ARCHITECTURE_PLAN.md` | Замысел контура ДЗ. |

Свою работу дописывать в конец `PROJECT_STATE.md` новым разделом — с причиной,
а не только с перечнем изменений. Причина потом стоит дороже диффа.

## Миграции — самое важное правило

**Никогда не запускать `supabase db push`.** Миграции применяются только
одобренным процессом (в облачной сессии — MCP `apply_migration`). После
применения SQL сохраняется в `supabase/migrations/` файлом, имя которого
ТОЧНО совпадает с записью в `supabase_migrations.schema_migrations` на удалённой
базе. Переименовывать нельзя.

Перед применением схему проверять на локальном Postgres 16 с эмуляцией RLS:

```sql
set role authenticated;
select set_config('request.jwt.claim.sub', '<uuid>', false);
-- ... проверки ...
reset role;
```

Две ловушки, на которых легко потерять час (обе — из реального опыта, §29.4):

1. `set_config` и проверяемая функция **в одном списке выборки** — порядок
   вычисления столбцов Postgres не гарантирует, результат случайный.
   Правильно — `set_config` в подзапросе `FROM`, он вычисляется раньше:
   ```sql
   select public.auth_is_staff_of_student('...')
   from (select set_config('request.jwt.claim.sub','<uuid>',true)) s;
   ```
2. Пробы под ролью-владельцем таблиц RLS **не проверяют** — владелец её
   обходит. Только `set role authenticated`.

## Устройство прав (тут живут почти все баги)

Права на курс проверяются функцией **`course_is_staff(course_id)`**. Она знает
про: платформенного админа, владельца курса, преподавателя группы, куратора
группы (легаси-слот `groups.curator_id`) и куратора курса (`course_curators`).

**Правило: любую новую проверку «персонал ли этот человек по курсу» делать
через `course_is_staff`, а не переписывать условия руками.** Ровно рассинхрон
ручных копий породил оба крупных бага сессии (§21 и §29): одни ветки знали про
новую роль, другие нет.

Ещё две вещи, которые стоит держать в голове:

- `groups.teacher_id` и `groups.curator_id` — ссылки на `teachers.id` /
  `curators.id` (таблицы ролей с `profile_id`), **не** напрямую на `profiles.id`.
- `is_admin_or_owner()` — это **платформенная роль**, а не «владелец курса».
  Владелец курса — `auth_is_course_owner(course_id)`. Их легко перепутать.

Права раздаёт не только PostgREST. С §31 через `course_is_staff` ходят ещё и
политики на **`realtime.messages`** — приватные каналы присутствия
`hw-review:<course_id>`. Топик приходит от клиента, поэтому его разбирает
`public.realtime_review_topic_course(text)`: на всём, что не подходит под
шаблон, она отдаёт `NULL`, а `course_is_staff(NULL) = false`. Проверять такой
предикат надо ровно так, как его вычисляет Realtime: `set role authenticated`
+ `request.jwt.claims` + `set_config('realtime.topic', …)`.

**Симптом RLS-бага, который выглядит как «нет данных»:** запросы ростера
используют `!inner`-джойны (`group_students → groups → students → profiles`).
Если прав на одну из таблиц нет, джойн молча выбрасывает строки, и интерфейс
показывает «нет учеников» вместо ошибки. Пустой список — повод проверить права,
а не данные.

## Три контура ДЗ — не перепутать

В базе исторически три системы домашних заданий:

| Контур | Таблицы | Состояние |
|---|---|---|
| Легаси | `homeworks`, `homework_submissions` | **0 строк**, мёртв |
| Homework V2 | `homework_templates`, `homework_assignments` | **0 строк**, скрыт из меню |
| **Тем курса** | `topic_homework*` | **живой, весь трафик здесь** |

Работать нужно с третьим. Первые два ещё встречаются в коде и в старых тестах —
не принимать их за актуальные. Роуты `/my-homeworks` (V2, скрыт) и
`/my-homework` (текущий) отличаются одной буквой; это ловушка, см. §23.3.

## Тесты

`npx tsc --noEmit`, `npx vite build`, `npx vitest run <файл>`.

Полный `vitest run` в облачной песочнице упирается в таймаут — прогонять
точечно по затронутым файлам.

**Осторожно с тестами «по тексту исходника».** В `catalog-qa.test.ts` и
соседних много проверок вида `expect(src).toContain('...')`. Они молча гниют
при рефакторинге: за одну сессию нашлось **три** таких теста, которые падали
задолго до правок, потому что код переименовали, а строку в тесте нет.
Если такой тест упал — сначала проверить `git show HEAD:<файл>`, не был ли он
сломан раньше. Новые проверки писать поведенческими.

`CourseProgramPage.program.test.tsx` не укладывается в таймаут песочницы —
проверено на чистом `HEAD`, это не регрессия правок.

E2E (`e2e/topic-homework-cycle.spec.ts`) из облачной песочницы не запускается:
egress-прокси блокирует `*.supabase.co`. По той же причине не поднять
websocket Realtime — присутствие (§31) вживую отсюда не проверить.

## Что проверено вживую, а что нет

Полный цикл ДЗ владелец прошёл руками 2026-07-30 и подтвердил (§28): сдача
скриншотом → уведомление и бейджи преподавателю → разбор с рамками → вердикт →
ученик видит пометки и оценку.

Не проверено кликом:
- обход всех пунктов меню обеими ролями (после разбиения бандла постранично,
  §25.3, сбой проявляется только на конкретной странице);
- каталог: раздел математики (переписанный путь) против физики в режиме тем;
- права куратора курса (§29) — на проде нет ни одного куратора;
- присутствие в проверке (§31) — нужны два аккаунта персонала на одном курсе
  одновременно; из песочницы websocket не поднять.

## Отложенные хвосты

- Гонка в `course_join_accept`: два первых ученика курса могут создать по
  отдельной группе (`groups.course_id` без уникального ограничения). §21.
- Мёртвый `HomeworksPage.tsx` — больше не роутится, но лежит в репозитории.
- Уборка хрупких текстовых тестов (см. выше).
- На Vercel стоит включить **Skew Protection** — тогда вкладки, открытые до
  деплоя, продолжат получать файлы своей версии. §27.5.
