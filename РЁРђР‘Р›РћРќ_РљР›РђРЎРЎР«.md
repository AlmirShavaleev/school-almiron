# Шаблон → классы: материал и задачи из каркаса видны во всех подгруппах

**Кому:** чат тестов (автор §162/§164 — задачи к уроку и прикрепление из каталога).
**Ветка:** `work/template-sync`, от свежего `main`.
**Раздел PROJECT_STATE:** **§172** — номер выдан оркестратором.
**Заведено:** 2026-09-13. Карточка `board/025`.

## Что случилось

13.09 в 19:17 владелец прикрепил из каталога 10 задач к теме «Кинематика.
Равномерное и равноускоренное движение. Теория» курса **«Физика ЕГЭ
Шаблон»** — `attach_catalog_tasks_to_topic` отработала, в
`test_variants` есть набор `9ea757e2…` с `topic_id`, 10 строк
`test_variant_items`. То есть §164 работает. А владелец «нигде не может
это увидеть», потому что:

1. в шаблоне нет учеников — там задачи видит только преподаватель в
   рубрике «Задачи» окна темы («ученики ещё не открывали»);
2. в трёх живых классах физики (10А — 16 учеников, 11А — 10, Ученики
   2026-2027 — 3) этой темы **задач нет**: копии классов сделаны раньше,
   а связи «тема шаблона → тема класса» в базе не существует. Всё, что
   добавляется в шаблон после копирования, — задачи, видео, файлы, ДЗ, —
   остаётся в шаблоне. Та же дыра всплыла 13.09 с видео №3 по
   математике (оркестратор разнёс шесть строк по классам руками).

Модель работы владельца, сказано прямо: **«основной материал мы добавляем
в курсе каркаса, а всё, что там есть, видно и по подгруппам»**. Шаблон —
мастер; классы — его отражения плюс своё. Сейчас платформа этого не
умеет, а §164 закрыл дыру только для новых копий курса.

## Что построить

### 1. Линейка происхождения (миграция, только добавляющая)

Столбцов линейки, которые можно переиспользовать, **нет**:
`topics.source_template_id` ссылается на `lesson_templates`,
`topic_material_items.source_topic_material_id` — на мёртвую
`topic_materials` (0 строк). Не трогать их и не перевешивать FK. Новые:

- `modules.source_module_id → modules(id) on delete set null`;
- `topics.source_topic_id → topics(id) on delete set null`;
- `topic_material_items.source_item_id → topic_material_items(id) on delete set null`;
- `topic_homework.source_homework_id → topic_homework(id) on delete set null`;
- `topic_homework_files.source_file_id → topic_homework_files(id) on delete set null`.

Уникальных индексов на новые столбцы **не ставить**: одна строка
шаблона отражается в нескольких копиях (индекс
`topic_material_items_source_uniq` на старом столбце — из другой
линейки, он и не позволил бы этого). Индекс обычный, по столбцу, — для
триггера.

Набор задач к уроку отдельной линейки не требует: у темы он один
(частичный уникальный индекс по `test_variants.topic_id`), связь идёт
через тему; строки `test_variant_items` сопоставляются по `task_id`.

`course_copy_stage` / `course_copy_topic_content` / `topic_copy_stage`
заполняют эти столбцы при копировании — всегда, не только из шаблона
(линейка от любого источника безвредна, а синхронизация ниже смотрит
только на `courses.is_template`).

### 2. Заполнение линейки задним числом (одноразово, в той же миграции)

На проде 3 шаблона и 7 копий (`courses.copied_from_course_id`). Проверено
оркестратором 13.09: у всех семи копий **100 % тем** однозначно
сопоставляются с темой шаблона по четвёрке (`modules.title`,
`modules.order_index`, `topics.title`, `topics.order_index`);
сопоставление по одним названиям даёт 2–4 двусмысленности на курс —
поэтому порядок обязателен. Модули: по (`title`, `order_index`);
лишние модули класса (у 11А их 14 против 13 в шаблоне) остаются без
источника — это своё.

Материалы: по (`kind`, `coalesce(storage_path, url, content)`) внутри
пары тем; если в теме несколько одинаковых — по `position`. Особый
случай — «Физика ЕГЭ 11А класс» (`2e40ec74…`): скопирован до §101,
файлы перезалиты под другими путями, 77 строк не совпадут по пути —
для них запасной ключ (`kind`, `file_name`, `size_bytes`, `position`).
После заполнения выведи в отчёт по каждому классу: тем всего / связано,
материалов всего / связано / осталось своих, ДЗ связано. Число «своих»
у шести классов, кроме физики 11А, должно быть 0 (проверено: копии
побайтно равны шаблону, включая шесть видео №3, разнесённых 13.09).

ДЗ: `topic_homework` по паре тем (у темы одно ДЗ, `unique(topic_id)`),
файлы ДЗ — по (`storage_path`, `position`).

Миграция — по правилам `MIGRATIONS.md`: сначала `apply_migration`,
прочитать версию из `schema_migrations`, потом имя файла. Заполнение
линейки — `update`, ничего не удаляется и не вставляется.

### 3. Синхронизация шаблон → копии

Одна definer-функция `template_sync_topic(p_template_topic_id uuid)`
и триггеры на `topic_material_items`, `topic_homework`,
`topic_homework_files`, `test_variants`, `test_variant_items`, `topics`,
`modules`, которые зовут её только когда строка принадлежит курсу с
`is_template = true`. Что она делает для каждой темы-копии
(`topics.source_topic_id = p_template_topic_id`):

| В шаблоне | В копии |
|---|---|
| добавлен материал | вставить копию с `source_item_id`; `storage_path`/`url` те же (§101 — файлы не дублируются); `position` как в шаблоне; `created_by = auth.uid()` |
| материал изменён (название, адрес, видимость, рубрика, позиция) | обновить строку с этим `source_item_id` |
| материал удалён | удалить строку с этим `source_item_id` (FK `set null` тут не годится — удалять до, в триггере `before delete`, или хранить и чистить по списку) |
| задача добавлена в набор темы | добавить в набор копии (создав набор, если его нет — тем же способом, что `attach_catalog_tasks_to_topic`), тот же `task_id`, `points`, `grading_type`, порядок как в шаблоне |
| задача убрана из набора | убрать из копии; **если по ней есть ответы учеников** — оставить и записать в результат функции (`kept_with_answers`), не терять чужие ответы молча |
| порядок задач изменён | повторить в копиях |
| ДЗ создано / текст, файлы изменены | создать/обновить с `source_homework_id`; **`is_published`, `due_at` не переносятся** — это классное |
| новая тема в модуле шаблона | создать в каждом модуле-копии с `source_topic_id`, `is_open` по правилу копирования `nullif(is_open, true)`, `available_from` не переносить; содержимое — через ту же синхронизацию |
| новый модуль в шаблоне | создать в копиях с `source_module_id` |
| тема / модуль переименованы | переименовать в копиях |
| порядок тем / модулей изменён | повторить в копиях: связанные темы и модули получают `order_index` шаблона; свои модули/темы класса (без источника) сохраняют номер, при совпадении номеров своё идёт после шаблонного (`order_index` + 0.5 → пересчёт целых). Для сравнения порядок должен совпадать со сравнением в клиенте (`order_index`, затем `created_at`) |
| тема / модуль удалены в шаблоне | удалить в копии, **если по ней нет следов учеников** (отметок в `topic_section_marks`, ответов на задачи, попыток ДЗ, отклонений плана); есть следы — оставить и записать в `template_sync_issues` (`kind='delete_kept'`), чтобы преподаватель убрал руками, когда решит |

**Не переносится никогда:** `is_open`, `available_from`, учебный план,
`due_at`, `is_published` ДЗ, отметки, ответы, присутствие. Расписание и
открытие — про класс, а не про каркас (§151). Всё остальное — **любая**
правка каркаса — подтягивается в классы автоматически, без кнопки
«синхронизировать» (решение владельца 13.09: «все изменения в каркасе
автоматически подтягиваются в курсы»). Кнопка «Повторить» на плашке
расхождений — не исключение, а починка того, что не прошло.

Синхронизация идёт в той же транзакции, что и правка шаблона. Объём
известен: у одной темы ≤ 3 копий, материалов в теме ≤ 10, — триггер не
станет дорогим. Если правка шаблона не смогла примениться к копии
(например, конфликт уникального индекса), правка шаблона **не
откатывается**, а расхождение записывается в новую таблицу
`template_sync_issues(template_topic_id, copy_topic_id, kind, detail,
created_at)`, которую видит преподаватель (см. UI). Молчаливый откат
правки владельца — худший из исходов.

Права: триггеры definer, но входная правка проходит обычную RLS
шаблона (`topic_material_can_manage`), так что синхронизация не
расширяет никому прав — она лишь повторяет то, что уже разрешено в
шаблоне.

### 4. Строки-отражения в классе

Строка класса с непустым `source_*_id` — отражение. В окне темы
класса у преподавателя такая строка помечена «из шаблона», **править и
удалять её нельзя** (кнопки скрыты, подсказка «меняется в шаблоне
курса»); своё в классе добавляется и правится как сейчас. Для задач к
уроку — то же: набор, у которого тема связана с шаблоном, в классе не
редактируется (нет «Подобрать в каталоге», нет стрелок и крестика),
кнопка ведёт в тему шаблона: «Задачи задаются в шаблоне → открыть».
Ученик разницы не видит.

Причина запрета, а не «локальная правка отвязывает»: отвязка тихо
делает из отражения своё, и через месяц никто не помнит, почему в 10А
видео другое. Если владельцу понадобится классное отклонение — это
отдельное решение, не здесь.

### 5. Что видит преподаватель в шаблоне

- В окне темы шаблона — строка сверху: «Каркас курса · изменения видны
  в 3 классах: 10А, 11А, Ученики 2026-2027» (по `copied_from_course_id`
  с фильтром `is_active`); если копий нет — «копий курса пока нет».
- После «Прикрепить к теме» из каталога тост: «Прикреплено 10 задач ·
  в 3 классах» — число из результата RPC (`attach_catalog_tasks_to_topic`
  возвращает `jsonb`, добавь `copies_synced`).
- Если есть строки в `template_sync_issues` по этой теме — жёлтая
  плашка со списком, кнопка «Повторить» (`template_sync_topic` можно
  звать руками — RPC для персонала курса-шаблона).

### 6. Одноразовый догон после миграции

Когда линейка заполнена, прогнать `template_sync_topic` по всем темам
трёх шаблонов один раз (в миграции или отдельным вызовом — на твой
выбор, но записать, что сделано). Ожидаемый результат на проде: 10
задач «Кинематики» появятся в трёх классах физики; всё остальное уже
совпадает (проверено), поэтому вставок кроме этих трёх наборов быть не
должно — если появились другие, это сигнал, что сопоставление шага 2
разошлось, остановись и напиши.
